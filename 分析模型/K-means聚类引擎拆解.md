# K-means 通用聚类引擎 · 多模块算法拆解

本拆解定义 K-means 的完整聚类链路：**白名单校验 → 特征工程（原生列派生）→ 编码 → 标准化 → 选 K → 聚类 → 画像**。K-means 是**通用聚类引擎**，只干一件事：把相似的行聚到一起；用途由"喂哪几列"决定。因此 K-means 按白名单拆成多个**独立模块**，每个模块 = 一份写死配置（用途名 + 输入表类型 + 白名单 + 命名标签）。

**与 RFM 的关系 = 降级兜底（非并列）**：RFM 能跑（HardBlock 齐）→ 用 RFM 8 群、**不启动** K-means 用户分层模块；RFM `skipped` → **降级到 K-means `USER_SEG`（用户分层）模块（仅此模块）**，不碰其他 K-means 模块；`USER_SEG` 也 `skipped`（核心列不齐）→ 整个分层 `skipped`。

### 模块总览（写死配置表 · 共 6 类聚合）

| 模块 | 具体作用（聚出来的群拿去干什么） | 输入表类型 | 核心必选（原生列） | 扩展可选（原生列） |
|---|---|---|---|---|
| `USER_SEG`（用户分层） | 把用户按"消费力+活跃度(+频次)"聚成价值群：高消费活跃群重点维护、高消费沉睡群发券召回、低价值群控制营销投入（RFM 跑不通时的兜底分层） | 订单明细表 | 用户ID、订单实付金额、订单时间 | 订单ID、注册日期、商品类目、退款金额、商品单价、城市、性别 |
| `SKU_SEG`（商品聚类） | 把商品按"价格带+销量+毛利"聚成商品群：找出高毛利滞销品做促销、低毛利爆款配捆绑、划定价格带支撑定价与选品 | 商品表 | 商品ID、商品单价、购买数量、商品成本 | 商品类目、类目ID、类目编码、品牌、商品规格、库存、原价、运费 |
| `GEO_SEG`（地域聚类） | 把省份/城市按"消费力+客单价+履约成本"聚成地域群：高消费区重点铺货、高运费低客单区调整包邮门槛，支撑区域定价与仓储布局 | 用户-订单表（带地理） | 省份、用户ID | 城市、邮编、运费、商品类目、订单实付金额、订单ID |
| `ACTIVITY_SEG`（活跃行为/作息聚类） | 把用户按"活跃时段+行为构成+粘性"聚成作息群（夜猫子/白天党/低频浏览客）：按群选推送时间、排活动档期，提升触达打开率 | 行为事件表 | 用户ID、事件时间、行为类型 | 在站时长、浏览页面数、访问次数、设备类型、会话开始时间、平台、流量来源 |
| `CATEGORY_SEG`（类目偏好聚类） | 把用户按"偏好哪些类目+偏好强度"聚成兴趣群：按群做个性化推荐与交叉销售（母婴群推玩具）、指导品类运营圈人 | 订单-商品明细表 | 用户ID、商品类目、购买数量 | 类目ID、品牌、商品ID、折扣金额、商品单价、订单时间 |
| `CHURN_SEG`（流失风险聚类） | 把用户按"静默时长+历史价值+负向行为"聚成流失风险群：高价值高风险群优先挽留（专属客服/大额券）、低价值高风险群放弃投入，让挽留预算花在刀刃上 | 用户级宽表 | 用户ID、最后活跃时间、订单时间 | 注册日期、订单实付金额、订单ID、退订状态、客诉次数、注销时间、退款金额 |

### 模块适配性说明（6 个模块均天然适配 · 引擎硬约束）

K-means（欧氏距离 + 均值质心）天生只适合**数值型、团状、密度相近**的数据；"肘部 + 轮廓系数"选 K 同理。本引擎保留的 6 个模块，特征工程后**均为"实体级数值宽表"**，直接跑、无特殊前提：

| 档 | 模块 | 判定与硬约束 |
|---|---|---|
| ✅ 天然适配 | `USER_SEG` / `SKU_SEG` / `GEO_SEG` / `ACTIVITY_SEG` / `CATEGORY_SEG` / `CHURN_SEG` | 特征工程后均为"实体级数值宽表"：`USER_SEG` 等用户群为 $M/R/F$、毛利率、静默天数、时段分布、类目占比；`GEO_SEG` 则是**按 省份 聚合成地域级数值指标（ARPU、客单价、订单密度）后再聚类**——本质仍是纯数值欧氏距离，直接跑。（唯一工程注意：单省份样本过少时聚合指标不稳，须设最小分组样本数 `MIN_GROUP_N`，可配常量，过滤后再聚。） |
### 逐模块白名单明细（按映射词典原生列 · 每列标注类型与编码）

> 类型标注约定（与下方"编码器函数"段对应）：`主键`=不参与距离，仅分组/回贴；`数值`=StandardScaler 标准化；`无序`=OneHot 拆 0/1（高基数 nunique>20 剔除）；`日期`=先派生间隔/时长再当数值。（`文本`、`有序` 类型已整体移除——`文本`：本引擎不支持文本聚类，NLP 向量高维稀疏、欧氏距离失效，且 6 模块均无文本列，评论类分析应改走情感分类/主题提取；`有序`：唯一有序列 评分星级 随 REVIEW_SEG 删除后已无任何模块使用，属死分支，未来若新增带等级/星级的模块再按 OrdinalEncoder 补回。）

#### 1. USER_SEG · 用户价值/行为分层（RFM 降级兜底）
- **具体作用**：把用户按"消费力 + 活跃度（+频次）"聚成价值群，直接指导营销投入——高消费活跃群重点维护、高消费沉睡群发券召回、低价值群控制投入；是 RFM 跑不通时的兜底分层。
- **输入表**：订单明细表（模块内先按 用户ID 聚合成用户级宽表，再聚类）。
- **核心必选（原生列 · 类型标注）**：
  - `用户ID`（主键，不进距离）
  - `订单实付金额`（数值→StandardScaler，特征工程派生 $M$）
  - `订单时间`（日期→派生 $R=$ 今天−最近订单时间）
  - *为何这 3 列*：用户ID 定位谁、金额出消费、时间出活跃度，是不可替代骨架。**比 RFM 的 $C_{core}$ 宽松一档**（RFM 还要 订单ID），故 RFM 因缺 订单ID `skipped` 时本模块仍能跑 → 降级成立。
- **扩展可选（原生列 · 类型标注）**：`订单ID`（主键，追加 $F$=Nunique，有则算、无则只用 $M+R$ 两维）、`注册日期`（日期→派生客户年限）、`商品类目`（无序→OneHot，高基数剔除）、`退款金额`（数值→派生退款率）、`商品单价`（数值）、`城市`（无序→OneHot，高基数剔除）、`性别`（无序→OneHot）。
- **特征工程输出（实体级宽表 `df_feat` 二级列 · 按 用户ID GroupBy）**：

| 层次 | 二级列 | 类型/编码 | 来源原始列 | 是否需要二级计算 | 说明 |
|---|---|---|---|---|---|
| 主键 | `用户ID` | 主键 | `用户ID` | 否 | 按 `用户ID` GroupBy 分组，聚合后仅作簇标签回贴 |
| 核心派生列 | `M` | 数值 | `订单实付金额` | 是 | $M = \sum \text{订单实付金额}$，核心必出 |
| 核心派生列 | `R` | 数值 | `订单时间` | 是 | $R = T_{ref} - \max(\text{订单时间})$，核心必出；日期派生间隔天数 |
| 扩展原始列 | `商品类目` | 无序→OneHot | `商品类目` | 否 | 该用户最常购类目（mode）或按用户 OneHot 占比；高基数剔除 |
| 扩展原始列 | `城市` | 无序→OneHot | `城市` | 否 | 众数城市；高基数剔除 |
| 扩展原始列 | `性别` | 无序→OneHot | `性别` | 否 | 直接保留或取众数 |
| 扩展原始列 | `商品单价` | 数值 | `商品单价` | 否 | 该用户均值商品单价（原始数值列聚合代表值） |
| 扩展派生列 | `F` | 数值 | `订单ID` | 是 | $F = \text{Nunique}(\text{订单ID})$，扩展存在才出 |
| 扩展派生列 | `客单价` | 数值 | `订单ID` + `订单实付金额` | 是 | $= M/F$，需 `订单ID` 存在 |
| 扩展派生列 | `客户年限` | 数值 | `注册日期` | 是 | $= T_{ref} - \min(\text{注册日期})$，日期派生 |
| 扩展派生列 | `退款率` | 数值 | `退款金额` + `订单实付金额` | 是 | $= \sum \text{退款金额} / \sum \text{订单实付金额}$ |

> **核心原始列（直接保留）**：本模块为聚合型，核心原始列 `订单实付金额`/`订单时间` 已分别被聚成 `M`/`R`，不单独作为 `df_feat` 列保留。扩展原始列则按用户取代表值或 OneHot 后直接进宽表。

#### 2. SKU_SEG · 商品聚类
- **具体作用**：把商品按"价格带 + 销量 + 毛利"聚成商品群——找出高毛利滞销品做促销清库存、低毛利爆款配捆绑拉利润、划定价格带支撑定价与选品决策。
- **输入表**：商品表（每行一个 商品ID / SKU）。
- **核心必选（原生列 · 类型标注）**：`商品ID`（主键，不进距离）、`商品单价`（数值→StandardScaler，价格带）、`购买数量`（数值→StandardScaler，销量）、`商品成本`（数值→StandardScaler，毛利=单价−成本）。
- **扩展可选（原生列 · 类型标注）**：`商品类目`（无序→OneHot）、`类目ID`（无序→OneHot，高基数剔除）、`类目编码`（无序→OneHot，高基数剔除）、`品牌`（无序→OneHot，高基数剔除）、`商品规格`（无序→OneHot，高基数剔除）、`库存`（数值）、`原价`（数值）、`运费`（数值）。
- **特征工程输出（实体级宽表 `df_feat` 二级列 · 无聚合，每行已是 商品ID）**：

| 层次 | 二级列 | 类型/编码 | 来源原始列 | 是否需要二级计算 | 说明 |
|---|---|---|---|---|---|
| 主键 | `商品ID` | 主键 | `商品ID` | 否 | 每行已是商品，仅作簇标签回贴 |
| 核心原始列（直接保留） | `商品单价` | 数值 | `商品单价` | 否 | 原始列直接保留（价格带） |
| 核心原始列（直接保留） | `购买数量` | 数值 | `购买数量` | 否 | 原始列直接保留（销量） |
| 核心原始列（直接保留） | `商品成本` | 数值 | `商品成本` | 否 | 原始列直接保留（毛利基础） |
| 核心原始列（直接保留） | `商品类目` | 无序→OneHot | `商品类目` | 否 | 原始列直接保留，OneHot 编码 |
| 核心派生列 | `毛利率` | 数值 | `商品单价` + `商品成本` | 是 | $= (\text{商品单价} - \text{商品成本}) / \text{商品单价}$ |
| 核心派生列 | `销售额` | 数值 | `商品单价` + `购买数量` | 是 | $= \text{商品单价} \times \text{购买数量}$ |
| 扩展原始列（直接保留） | `库存` | 数值 | `库存` | 否 | 原始列直接保留 |
| 扩展原始列（直接保留） | `原价` | 数值 | `原价` | 否 | 原始列直接保留 |
| 扩展原始列（直接保留） | `运费` | 数值 | `运费` | 否 | 原始列直接保留 |
| 扩展原始列（直接保留） | `类目ID` | 无序→OneHot | `类目ID` | 否 | 原始列直接保留，高基数剔除 |
| 扩展原始列（直接保留） | `类目编码` | 无序→OneHot | `类目编码` | 否 | 原始列直接保留，高基数剔除 |
| 扩展原始列（直接保留） | `品牌` | 无序→OneHot | `品牌` | 否 | 原始列直接保留，高基数剔除 |
| 扩展原始列（直接保留） | `商品规格` | 无序→OneHot | `商品规格` | 否 | 原始列直接保留，高基数剔除 |
| 扩展派生列 | — | — | — | — | 本模块无扩展派生列 |

#### 3. GEO_SEG · 地域聚类
- **具体作用**：把省份/城市按"消费力 + 客单价 + 履约成本"聚成地域群——高消费区重点铺货、高运费低客单区调整包邮门槛，支撑区域定价与仓储布局。
- **适配说明**：本模块聚的是**地域**（`省份` 为分组键，主键，不进距离），特征是地域级派生数值（地域 ARPU、客单价、订单密度），属纯数值 K-means，直接跑。唯一工程注意：单省份样本过少时聚合指标不稳，须设最小分组样本数（同 `MIN_GROUP_N`，可配）过滤后再聚。
- **输入表**：用户-订单表（带地理字段）。
- **核心必选（原生列 · 类型标注）**：`省份`（主键，地域分组键，不进距离；按它聚合成地域级数值行）、`用户ID`（主键，聚合）。
- **扩展可选（原生列 · 类型标注）**：`城市`（无序→OneHot，高基数剔除）、`邮编`（无序→OneHot，高基数剔除）、`运费`（数值）、`商品类目`（无序→OneHot）、`订单实付金额`（数值）、`订单ID`（主键）。
- **特征工程输出（实体级宽表 `df_feat` 二级列 · 按 省份 GroupBy）**：

| 层次 | 二级列 | 类型/编码 | 来源原始列 | 是否需要二级计算 | 说明 |
|---|---|---|---|---|---|
| 主键 | `省份` | 主键 | `省份` | 否 | 按 `省份` GroupBy 分组，聚合后仅作簇标签回贴 |
| 核心派生列 | `地域ARPU` | 数值 | `订单实付金额` + `用户ID` | 是 | $= \sum \text{订单实付金额} / \text{用户数}$（按省份聚合） |
| 核心派生列 | `地域客单价` | 数值 | `订单实付金额` + `订单ID` | 是 | $= \sum \text{订单实付金额} / \text{订单数}$（按省份聚合） |
| 核心派生列 | `地域订单密度` | 数值 | `订单ID` + `用户ID` | 是 | $= \text{订单数} / \text{用户数}$（按省份聚合） |
| 扩展原始列（直接保留/代表值） | `城市` | 无序→OneHot | `城市` | 否 | 众数城市；高基数剔除 |
| 扩展原始列（直接保留/代表值） | `邮编` | 无序→OneHot | `邮编` | 否 | 高基数剔除 |
| 扩展原始列（直接保留/代表值） | `运费` | 数值 | `运费` | 否 | 均值运费（按省份聚合代表值） |
| 扩展原始列（直接保留/代表值） | `商品类目` | 无序→OneHot | `商品类目` | 否 | 众数类目 |
| 扩展原始列（被消耗） | `订单ID` | 主键 | `订单ID` | 否 | 仅用于计数，不保留为 `df_feat` 列，不进距离 |

> **核心原始列（直接保留）**：本模块为聚合型，核心原始列 `订单实付金额`/`用户ID` 已分别被聚成 `地域ARPU`/`地域订单密度`，不单独作为 `df_feat` 列保留。

#### 4. ACTIVITY_SEG · 活跃行为/作息聚类
- **具体作用**：把用户按"活跃时段 + 行为构成 + 粘性"聚成作息群（夜猫子/白天党/低频浏览客）——按群选推送时间、排活动档期，提升触达打开率与转化。
- **输入表**：行为事件表（每行一个埋点事件）。
- **核心必选（原生列 · 类型标注）**：`用户ID`（主键，聚合）、`事件时间`（日期→派生时段/频次）、`行为类型`（无序→OneHot，行为构成：浏览/加购/下单/分享）。
- **扩展可选（原生列 · 类型标注）**：`在站时长`（数值）、`浏览页面数`（数值）、`访问次数`（数值）、`设备类型`（无序→OneHot）、`会话开始时间`（日期→派生）、`平台`（无序→OneHot）、`流量来源`（无序→OneHot）。
- **特征工程输出（实体级宽表 `df_feat` 二级列 · 按 用户ID GroupBy）**：

| 层次 | 二级列 | 类型/编码 | 来源原始列 | 是否需要二级计算 | 说明 |
|---|---|---|---|---|---|
| 主键 | `用户ID` | 主键 | `用户ID` | 否 | 按 `用户ID` GroupBy 分组，聚合后仅作簇标签回贴 |
| 核心原始列（直接保留） | `行为类型` | 无序→OneHot | `行为类型` | 否 | 直接保留（浏览/加购/下单/分享） |
| 核心派生列 | `日活频次` | 数值 | `事件时间` | 是 | $= \text{事件数} / \text{活跃天数}$ |
| 核心派生列 | `活跃时段分布` | 数值（多列） | `事件时间` | 是 | 按小时分箱 → 深夜/上午/下午/晚间各时段占比 |
| 核心派生列 | `行为漏斗转化比` | 数值 | `行为类型` | 是 | 下单事件数 / 加购事件数（或各行为占比） |
| 扩展原始列（直接保留/代表值） | `在站时长` | 数值 | `在站时长` | 否 | 均值 |
| 扩展原始列（直接保留/代表值） | `浏览页面数` | 数值 | `浏览页面数` | 否 | 均值 |
| 扩展原始列（直接保留/代表值） | `访问次数` | 数值 | `访问次数` | 否 | 求和 |
| 扩展原始列（直接保留/代表值） | `设备类型` | 无序→OneHot | `设备类型` | 否 | 众数 |
| 扩展原始列（直接保留/代表值） | `平台` | 无序→OneHot | `平台` | 否 | 众数 |
| 扩展原始列（直接保留/代表值） | `流量来源` | 无序→OneHot | `流量来源` | 否 | 众数 |
| 扩展派生列 | `会话时长` | 数值 | `会话开始时间` | 是 | 均值会话时长 |

#### 5. CATEGORY_SEG · 类目偏好聚类
- **具体作用**：把用户按"偏好哪些类目 + 偏好强度"聚成兴趣群——按群做个性化推荐与交叉销售（如母婴群推玩具）、为品类运营圈定目标人群。
- **输入表**：订单-商品明细表（每行一笔订单的一行商品）。
- **核心必选（原生列 · 类型标注）**：`用户ID`（主键，聚合）、`商品类目`（无序→OneHot，偏好维度）、`购买数量`（数值→StandardScaler，偏好强度）。
- **扩展可选（原生列 · 类型标注）**：`类目ID`（无序→OneHot，高基数剔除）、`品牌`（无序→OneHot，高基数剔除）、`商品ID`（主键）、`折扣金额`（数值）、`商品单价`（数值）、`订单时间`（日期→派生）。
- **特征工程输出（实体级宽表 `df_feat` 二级列 · 按 用户ID GroupBy）**：

| 层次 | 二级列 | 类型/编码 | 来源原始列 | 是否需要二级计算 | 说明 |
|---|---|---|---|---|---|
| 主键 | `用户ID` | 主键 | `用户ID` | 否 | 按 `用户ID` GroupBy 分组，聚合后仅作簇标签回贴 |
| 核心原始列（直接保留） | `商品类目` | 无序→OneHot | `商品类目` | 否 | 偏好维度，直接 OneHot（每类目一列） |
| 核心派生列 | `各类目消费占比` | 数值（多列） | `商品类目` + `商品单价` | 是 | $= \text{类目消费} / \text{总消费}$ |
| 核心派生列 | `跨类目广度` | 数值 | `类目ID` | 是 | $= \text{Nunique}(\text{类目ID})$ |
| 核心派生列 | `购买数量` | 数值 | `购买数量` | 是 | 按用户求和（偏好强度） |
| 扩展原始列（直接保留/代表值） | `类目ID` | 无序→OneHot | `类目ID` | 否 | 高基数剔除 |
| 扩展原始列（直接保留/代表值） | `品牌` | 无序→OneHot | `品牌` | 否 | 高基数剔除 |
| 扩展原始列（被消耗） | `商品ID` | 主键 | `商品ID` | 否 | 仅用于分组，不保留为 `df_feat` 列，不进距离 |
| 扩展原始列（直接保留/代表值） | `折扣金额` | 数值 | `折扣金额` | 否 | 按用户求和 |
| 扩展原始列（直接保留/代表值） | `商品单价` | 数值 | `商品单价` | 否 | 按用户均值 |
| 扩展派生列 | `最近购买间隔` | 数值 | `订单时间` | 是 | $= T_{ref} - \max(\text{订单时间})$ |

#### 6. CHURN_SEG · 流失风险聚类
- **具体作用**：把用户按"静默时长 + 历史价值 + 负向行为"聚成流失风险群——高价值高风险群优先挽留（专属客服/大额券）、低价值高风险群放弃投入，让挽留预算花在刀刃上。
- **输入表**：用户级宽表（含活跃与交易原生字段）。
- **核心必选（原生列 · 类型标注）**：`用户ID`（主键，不进距离）、`最后活跃时间`（日期→派生静默天数）、`订单时间`（日期→派生最近购买）。
- **扩展可选（原生列 · 类型标注）**：`注册日期`（日期→派生客户年限）、`订单实付金额`（数值）、`订单ID`（主键）、`退订状态`（无序→OneHot）、`客诉次数`（数值）、`注销时间`（日期→派生）、`退款金额`（数值）。
- **特征工程输出（实体级宽表 `df_feat` 二级列 · 按 用户ID GroupBy）**：

| 层次 | 二级列 | 类型/编码 | 来源原始列 | 是否需要二级计算 | 说明 |
|---|---|---|---|---|---|
| 主键 | `用户ID` | 主键 | `用户ID` | 否 | 按 `用户ID` GroupBy 分组，聚合后仅作簇标签回贴 |
| 核心派生列 | `静默天数` | 数值 | `最后活跃时间` | 是 | $= T_{ref} - \max(\text{最后活跃时间})$，核心必出；日期派生 |
| 核心派生列 | `历史消费` | 数值 | `订单实付金额` | 是 | $= \sum \text{订单实付金额}$，核心必出 |
| 核心派生列 | `投诉率` | 数值 | `客诉次数` + `订单ID` | 是 | $= \text{客诉次数} / \text{订单数}$，核心必出 |
| 核心派生列 | `最近购买` | 数值 | `订单时间` | 是 | $= T_{ref} - \max(\text{订单时间})$，核心必出；日期派生 |
| 扩展原始列（直接保留/代表值） | `退订状态` | 无序→OneHot | `退订状态` | 否 | 直接保留 |
| 扩展原始列（直接保留/代表值） | `客诉次数` | 数值 | `客诉次数` | 否 | 按用户求和 |
| 扩展原始列（直接保留/代表值） | `退款金额` | 数值 | `退款金额` | 否 | 按用户求和 |
| 扩展原始列（被消耗） | `订单ID` | 主键 | `订单ID` | 否 | 仅用于计算投诉率/历史消费，不保留为 `df_feat` 列，不进距离 |
| 扩展派生列 | `客户年限` | 数值 | `注册日期` | 是 | $= T_{ref} - \min(\text{注册日期})$，日期派生 |
| 扩展派生列 | `是否已注销` | 数值 | `注销时间` | 是 | 0/1 标记或注销间隔 |

> **核心原始列（直接保留）**：本模块为聚合型，核心原始列 `最后活跃时间`/`订单时间`/`订单实付金额` 已分别被聚成 `静默天数`/`最近购买`/`历史消费`，不单独作为 `df_feat` 列保留。

> 所有模块共用同一引擎管道（见下文"编码器函数"），仅白名单与特征工程派生式随模块而异；彼此独立、可并存。RFM 跑通则不启动 `USER_SEG`（用户分层），RFM `skipped` 才降级到 `USER_SEG`（用户分层）（仅此模块，不碰其他）。

### 降级路由规则（与 RFM 的衔接）

1. RFM 基座跑通 → 产出 8 群，结束；**不触发**任何 K-means 模块。
2. RFM `skipped`（无论何因）→ 检查 `USER_SEG` 核心白名单是否齐全：
   - 齐全 → **降级跑 `USER_SEG`（用户分层）**，不启动 `SKU_SEG`（商品聚类）等其他模块。
   - 不齐全 → 整个用户分层 `skipped`。
3. `USER_SEG`（用户分层）核心特意比 RFM $C_{core}$ 宽松一档（RFM 需 4 原生列，USER_SEG 核心只需 3 列——把 `订单ID` 降为扩展），使得"RFM 因缺 `订单ID` skipped"时 USER_SEG 仍能跑，降级才真正生效。

### 单模块内部链路（通用模板，以 USER_SEG 为例）

每个模块内部链路完全一致，仅"白名单列 + 特征工程派生式"随模块而异。

#### 1. 白名单校验（核心必选齐全才跑 · 类型见上方明细）

- `USER_SEG`（用户分层）核心必选（原生列）：$\{\text{用户ID},\ \text{订单实付金额},\ \text{订单时间}\}$
  - `用户ID`（主键，不进距离）
  - `订单实付金额`（数值，特征工程派生成 $M$）
  - `订单时间`（日期，特征工程派生 $R=$ 最近购买间隔天数）
- `USER_SEG`（用户分层）扩展可选（原生列）：$\{\text{订单ID},\ \text{商品类目},\ \text{注册日期},\ \text{退款金额}\}$
  - `订单ID`（主键，特征工程派生成 $F$ 与 客单价，有才算）
  - `商品类目`（无序，特征工程按用户取代表值或 OneHot，高基数 nunique>20 剔除）
  - `注册日期`（日期，特征工程派生客户年限，有才算）
  - `退款金额`（数值，特征工程派生退款率，有才算）
- 校验：核心必选 $\not\subset$ 原始列 → `return {"status":"skipped","module":"USER_SEG"}`；扩展可选按"存在才用"取。

#### 2. 特征工程（原生列 → 派生聚类特征）· MD 数学公式

- **白话**：白名单里的列是"原材料"，不能直接聚类（比如余额是每笔订单的金额，不是每人的总消费）。这步把原材料**聚合成每用户一行**的派生特征，才是 K-means 真正吃的数字。
- **取列**：白名单命中的原生列（核心必选 + 实际存在的扩展可选）。
- **派生公式示例**（按 用户ID GroupBy，核心 / 扩展公式见上方 USER_SEG 模块特征工程输出表）：
  $$M(u) = \sum \text{订单实付金额}_u \qquad (\text{核心派生，必算})$$
  $$R(u) = T_{ref} - \max(\text{订单时间}_u) \qquad (\text{核心派生；} T_{ref}=\text{分析当日})$$
  $$F(u) = \text{Nunique}(\text{订单ID}_u) \qquad (\text{扩展派生，需 订单ID 存在})$$
  $$\text{客单价}(u) = \frac{M(u)}{F(u)} \qquad (\text{扩展派生，需 订单ID 存在})$$
  $$\text{客户年限}(u) = T_{ref} - \min(\text{注册时间}_u) \qquad (\text{扩展派生，需 注册日期 存在})$$
  $$\text{退款率}(u) = \frac{\sum \text{退款金额}_u}{\sum \text{订单实付金额}_u} \qquad (\text{扩展派生，需 退款金额 存在})$$
- **输出列**：实体级宽表 `df_feat` 的分层输出（主键 / 核心原始列 / 核心派生列 / 扩展原始列 / 扩展派生列）及逐列处理，见 **USER_SEG 模块特征工程输出表**。通用模板：原始列直接保留的进 `df_feat` 不变；需要公式/聚合/日期派生的列在特征工程阶段算好，再交给编码器。
- **复杂度**：$O(n)$。

### 编码器函数（白名单驱动的类型分派器 · 无独立分类步骤）

#### 1. 三层职责（别混成一锅）

| 层 | 唯一职责 | 带不带类型 |
|---|---|---|
| **映射词典** | 列名归一化：把 `order_amount` / `pay_amt` / `实付` 全统一成标准键 `订单实付金额` | ❌ 只是别名表，不带类型 |
| **白名单**（每模块一份） | 声明本模块用哪些标准列 + 每列**写死类型标注**（数值 / 无序 / 日期 / 主键） | ✅ 类型真身在这 |
| **编码器函数** | 按**类型标签**分派到对应编码器，做数值化 | 只认类型，不认业务列名 |

> 一句话：**映射词典管"这列叫什么"，白名单管"这列是什么类型"，编码器管"按类型变成数字"**。类型是开发期写死在白名单每列上的，不是运行时判断的。

#### 2. 运行时调用链（传进来的原始列名怎么变数字）

```
原始列名(order_amt)
  → [映射词典] 归一化         → 标准键(订单实付金额)
  → [白名单]   挑列 + 定类型   → 声明本模块用哪些原始列、各列什么类型（仅用于指导特征工程，不进编码器）
  → [特征工程] 聚合 / 派生     → 实体级宽表 df_feat：列 = 二级派生特征(M/R/F/毛利率/地域ARPU/类目占比…)
                                    + 直接保留的类型化原始列(数值/无序)；每列自带类型标注；
                                    主键列被分组消耗、不进距离
  → [编码器]   读 df_feat 每列类型 → 分派 StandardScaler/OneHot → 纯数字矩阵 X
```

- 编码器与业务列**彻底解耦**：加一个新列？只在白名单加一行带类型标注，编码器代码一个字都不用改。反之若把业务判断写进编码器（如 `if 列名=="订单实付金额": StandardScaler`），每加一列就要改函数——正是早先否掉的"120 列分类字典"死路。

#### 3. 编码器函数结构（契约）

- **输入**：① 特征工程产出的**实体级特征宽表 `df_feat`**（每行一个实体，列为二级派生特征 + 直接保留的类型化原始列，每列已带类型标注）；② 列类型映射 `col_types`（`{特征列: 类型标签}`，由白名单原始列类型继承、派生列在特征工程阶段指定）。**注意：编码器不吃白名单原始列名**——白名单只用于"特征工程挑列 + 定类型"，原始列经聚合 / 派生后才变成 `df_feat` 的列。
- **输出**：一张纯数值特征矩阵 $X$（每行一个实体，业务列名已全部消失，变成数字列）。

```
def encode(df_feat, col_types):         # df_feat: 特征工程输出的实体级宽表；col_types: {特征列: 类型}
    X = []
    for col, dtype in col_types.items():# 遍历特征列，读类型标签
        if   dtype == "主键": continue                      # 跳过，仅分组/回贴
        elif dtype == "数值": X.append( StandardScaler(df_feat[col]) )
        elif dtype == "无序": X += OneHot( df_feat[col], drop_high_card=20 )
        elif dtype == "日期": X.append( StandardScaler(df_feat[col]) )  # 日期已在特征工程派生为间隔/时长数值
    return hstack(X)                     # 拼成矩阵 X
```

> 关键点：①函数体里**不出现任何具体业务列名**（如"订单实付金额"），只出现 4 个类型标签，是"类型 → 编码器"的纯查表分派器；②`df_feat[col]` 取的是**特征工程算出的列**（如 $M$、$R$、毛利率、地域 ARPU），不是白名单原始列名——聚合型模块里这些几乎全是二级派生列，无聚合模块（如 SKU_SEG 的商品单价）则是原始数值列直接保留进宽表，但同样经由特征工程输出、不再叫"白名单原始列"。

#### 5. 类型分派表（四类编码规则）

| 类型标签 | 编码器                       | 处理规则                                                                                                 |
| ---- | ------------------------- | ---------------------------------------------------------------------------------------------------- |
| `主键` | 跳过                        | 仅作分组键 / 回贴标签（用户ID、订单ID、商品ID 等），**不进距离**                                                              |
| `数值` | `StandardScaler`          | 逐列标准化（均值 0 方差 1）：涵盖 $M/R/$ 毛利率 / 地域ARPU / 类目占比 / 静默天数 等全部二级数值列。逐列清单见上方第 4 节全量收录表                     |
| `无序` | `OneHotEncoder`           | 拆 0/1 多列：商品类目、性别、退订状态、行为类型…。**高基数剔除（规则详见本表下方说明块）**：`nunique > 20` 的无序列直接剔除、不进聚类。逐个二级列处置见上方第 4 节全量收录表 |
| `日期` | 特征工程派生 → `StandardScaler` | 日期本身不直接聚；**派生归特征工程**（转成间隔/时长，如 $R = T_{ref} - \max(订单时间)$），编码器只对其执行 `StandardScaler`（与数值列同处理）        |

> **`文本`、`有序` 两类已移除**：
> - `文本 → NLP 向量化`：①TF-IDF/embedding 产出高维稀疏向量，欧氏距离在高维失效（维度灾难）、轮廓系数失真；②当前 6 模块白名单均无文本列，该分支是永远不会命中的死分支；③文本类需求（如评价分析）正确路子是情感分类 + 主题提取（有监督分类 / LDA），不是 K-means 聚类。若未来白名单出现文本列，一律**当高基数无序列处理→直接剔除**，不做向量化。
> - `有序 → OrdinalEncoder`：唯一有序列 `评分星级`（1<2<3<4<5）只存在于已删的 REVIEW_SEG，当前 6 模块无任何有序列，该分支同为死分支，按"每类必须有真实模块在用、零摆设"的标准移除。未来新增带评分/等级/星级/分档的模块时，再补回 `OrdinalEncoder`（须显式传 `categories` 顺序参数保序）——补回成本一行分支，无额外依赖。

**高基数剔除是什么（无序列专属规则）**

- **高基数** = 该列不重复值太多（high cardinality）。如 `性别` 只有 3 个值是低基数；`城市` 300+ 个、`品牌` 上千个、`类目ID`/`邮编` 几万个，都是高基数。
- **为什么必须剔**：无序列进距离前要 OneHot——把"1 列 N 个值"拆成"N 个 0/1 列"。低基数没事（`性别` 拆 3 列）；高基数会**维度爆炸**（`城市` 拆 300 列、`品牌` 拆上千列），且拆出的列极稀疏（绝大多数行为 0，几乎无信息），把欧氏距离搅乱、聚类质量下降、计算量暴涨。
- **判定标准（写死可配常量）**：`MAX_CARDINALITY = 20`。无序列 `nunique > 20` → 该列**整列剔除，不进聚类特征**（不是剔除行，也不代表该列没业务价值）。
- **想保留高基数信息的唯一正路**：由特征工程**先聚合成数值指标**再进距离（如 `GEO_SEG` 把 `省份` 聚成 地域ARPU/地域客单价，而非对省份 OneHot）。
- **禁用替代方案**：不用 target-encoding 救高基数列——它依赖目标变量，K-means 无监督无目标，等于偷塞业务判断，违反"无业务输入"硬约束。

#### 6. 澄清：没有“独立分类步骤”

白名单只**选列**、不**改值形式**（文字进白名单仍是文字），所以"文字 / 日期 → 数字"的编码步骤不可省。但**不存在运行时先扫描全表、判断每列该归哪类、再编码的环节**——类型在白名单上已随列写死，编码器只是"读标注 → 路由到对应编码器"。所谓"分类"发生在**开发期写白名单的那一刻**，不是运行期。

另重申：**编码器不直接吃白名单原始列名**。白名单只用于"特征工程挑列 + 定类型"，原始列经聚合 / 派生后变成实体级宽表 `df_feat` 的列，编码器吃的是 `df_feat` 的列（见第 2、3 节）。

#### 7. 合并成矩阵 $X$

各模块把"特征工程产出的实体级宽表（`df_feat`）按列类型编码后"的特征拼接成 $X$ 送聚类。实际喂入维度由开发者写死白名单时收紧（落在 $4\sim6$ 列），**不靠运行时 PCA 降维**（PCA 搅乱特征、破坏 B 命名）或业务精选（需人为判断、违反无业务输入）。

### K 值怎么处理（肘部 + 轮廓系数两法吻合定 K）

循环 $K \in [K_{min}, K_{max}]$（默认 $2\sim7$，业务约束收窄），对每个 $K$ 跑 KMeans 记录两个指标：

- 簇内平方和（越小越紧）：
  $$Inertia(K) = \sum_k \sum_{x \in C_k} \|x - \mu_k\|^2$$
- 轮廓系数（越大越分离）：
  $$Sil(K) = \frac{1}{n} \sum_i \frac{b(i) - a(i)}{\max(a(i), b(i))}$$

取两法**拐点 / 峰值位置吻合**的 $K$ 为最佳 $K^*$（单法易模糊，两法交叉验证更稳）。允许调用方 `k=N` 直接覆盖。若两法给出的 $K$ 不一致，缩小搜索区间复验或按业务偏好取舍。

**轮廓系数大表抽样（硬约束）**：$Sil(K)$ 复杂度为 $O(n^2)$，订单级/事件级大表（`ACTIVITY_SEG` 等）直接全量算会算死。写死规则：$n > 10000$ 时抽样计算（默认 `SIL_SAMPLE_SIZE = 10000`，随机抽样 + `random_state` 保复现，暴露为可配常量）；肘部图 $O(nK)$ 无此问题、始终全量。

质量前置：设 `random_state` 保复现；`n_init` 多跑取优；标准化已在特征工程阶段完成。

### K 定完怎么聚类

1. 以 $K^*$ 初始化 KMeans 并 `fit_predict(X)`：
   $$C(u) \in \{0,\ 1,\ \dots,\ K^*-1\}$$
2. **簇命名（写死通用描述词，无业务输入下的 B 方案）**：
   - **a. 簇画像（代码必算）**：数值列算每簇均值 $\mu_{k,j} = \frac{1}{|G_k|}\sum_{r \in G_k} x_{r,j}$；分类列算每簇众数 $mode_{k,j} = \arg\max_c\ count(G_{k,j}=c)$。
   - **b. 特征签名（代码）**：对每簇把各特征与全局比较，标成 高 / 低 / 中（数值列用均值 vs 全局均值，或分位；分类列取众数主导类目）：
     $$sig_{k,j} = \begin{cases} 高 & \mu_{k,j} > \mu_{global,j} \\ 低 & \mu_{k,j} < \mu_{global,j} \\ 中 & \text{其余} \end{cases}$$
   - **c. 描述词表（写死，通用统计语言、非业务）**：开发者一次性写死 `FEATURE_LABELS`，每特征对应 高 / 低 / 中 的描述词（如 总消费金额 → 高:"高消费" / 低:"低消费"、购买频率 → 高:"活跃" / 低:"沉睡"、最近购买间隔天数 → 高:"久未购" / 低:"近期购"）。**不依赖任何业务输入，与上传哪批数据无关。**
   - **d. 模板拼接（写死）**：`TEMPLATE = "{消费}{活跃}{复购}客"` 等骨架，把签名填入 → 稳定名如 `高消费沉睡久未购客`；并以 `C{k}_{描述}` 作为簇唯一身份键。
   - **说明**：B 产出的是"描述性"名（如 高消费低频客），非"业务语义"名（如 高价值核心客户）；在"只上传数据、不提供业务"的定位下，这是合理且可用的。命名基于 profile 签名而非 cluster id，对 K-means 标签漂移（label switching）鲁棒。
3. **输出**：每用户一行 + 簇标签 + 簇画像（各簇在所聚特征上的均值 / 众数、人数、占比）。

### 输出列

宽表新增 $[Cluster,\ \text{各特征均值},\ Cluster\_Size,\ Cluster\_Ratio]$；簇画像分布表（每簇人数 / 占比 + 各特征均值 / 众数）。

### K-means 可视化产出（可生成的图表与业务作用）

- **肘部 + 轮廓系数折线图（并排）**：数据来源 = 选 K 循环中 $Inertia(K)$ 与 $Sil(K)$ 两列 → 两线同框，拐点吻合处即为最佳 $K$；用于人工复核自动选 K 的合理性。
- **簇分布条形图**：各簇人数 → 看自然群规模是否均衡、有无极小单簇；用于判断是否需要合并小簇或调参。
- **簇画像雷达图**：各簇在所聚特征上的均值雷达叠加 → 对比自然群特征差异，辅助人眼核对 B 方案写死的描述性名字是否贴切（如"高消费低频次簇 = 高消费沉睡客"）。
- **特征二维散点图**（颜色 = 簇标签）：选两个代表特征（如 $M$ vs $R$）作坐标，簇标签上色 → 直观看自然群体在特征空间的分离度；若簇严重重叠，说明选的特征对分群贡献弱、需换特征。
