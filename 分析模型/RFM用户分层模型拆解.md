# RFM 用户分层模型 · 三段式算法拆解

> 拆解逻辑（用户定的尺子）：第一段 硬性阻断层 HardBlock（把门）→ 第二段 基座计算层 Base（立核心，最优先）→ 第三段 进阶探测层 Advanced（从核心往深里挖）。

## 第一段：硬性阻断层（HardBlock）—— 输入数据校验

- 校验对象：Pandas DataFrame 列名
- 必备列集：$C_{core} = \{\text{用户ID},\ \text{订单时间},\ \text{订单实付金额},\ \text{订单ID}\}$
  - 用户ID：分组主键
  - 订单时间：算 $R$（近度 Recency）
  - 订单实付金额：算 $M$（金额 Monetary）
  - 订单ID：算 $F$（频次 Frequency = 去重订单数）
- 阻断：若 $C_{core} \not\subset \text{原始列}$ → `return {"status":"skipped"}`（跳过非报错）
- 标注：`MD 算法阻断`
- **取列**：仅做列名存在性校验，不取数；要求原始表含上述 4 列方可进入 Base。

## 第二段：基座计算层（Base Calculation）—— 模型最核心分析

**目标**：流水订单明细表 → 每用户一行 $R/F/M$ 原始值 → 分箱打分 $(1\sim5)$ → 二值化交叉 → 8 大标准群体。

### 2.1 用户级指标聚合（User-level Aggregation）· MD 数学公式

- **取列**：从原始表取 $\{\text{用户ID},\ \text{订单时间},\ \text{订单ID},\ \text{订单实付金额}\}$ 四列；按 用户ID GroupBy，对每个用户算 $R/F/M$ 三个原始标量。
- **公式**：
$$R_{raw}(u) = T_{ref} - \max(\text{订单时间}_u)$$

其中 $T_{ref}$ = 分析基准日，**固定取当前分析当日或业务指定的某天快照**（不可取全表最新订单日——否则算出的是“距数据截止日”的偏移而非“距今天”的近度，会系统性压低所有用户 $R$、导致后续分群失真）。该天数差即用户“最近购买间隔天数”（对应映射词典同名列）。

$$F_{raw}(u) = \text{Nunique}(\text{订单ID}_u)$$

（**频次 = 该用户的去重订单笔数**。同一笔订单可能拆成多行明细，所以要按 订单ID 去重计数才能数“订单数”而非“商品行数”。
例：用户 A 的 订单ID 行 = $\{O1,\ O1,\ O2\}$ → 去重后 $\{O1,\ O2\}$ → $F_{raw}=2$ 笔订单。）

$$M_{raw}(u) = \sum \text{订单实付金额}_u$$

（**金额 = 该用户所有订单的实付金额加总**。
例：用户 A 三行 订单实付金额 = $\{100,\ 50,\ 200\}$ → $\sum=350$ → $M_{raw}=350$ 元。）

- **输出列**：用户级宽表 $[\text{用户ID},\ R_{raw},\ F_{raw},\ M_{raw}]$（每用户一行）。

### 2.2 分箱打分（Scoring / Binning）· MD 数学公式

- **取列**：取 2.1 输出 $[\text{用户ID},\ R_{raw},\ F_{raw},\ M_{raw}]$ 中的 $R_{raw}, F_{raw}, M_{raw}$ 三列（用户ID 仅作主键保留）。
- 对 $R/F/M$ 分别分箱（等频 5 分位或业务阈值）映射为 $1\sim5$ 分。$R$ 越大（越久未购）分越低；$F, M$ 越大分越高：
$$R_{score}(u) = Bin_{\downarrow}(R_{raw}(u),\ q=5)$$
（降序：最近 $=5$）
$$F_{score}(u) = Bin_{\uparrow}(F_{raw}(u),\ q=5)$$
$$M_{score}(u) = Bin_{\uparrow}(M_{raw}(u),\ q=5)$$
- **输出列**：宽表新增 $[R_{score},\ F_{score},\ M_{score}]$。

### 2.3 二值化与群体映射（Segmentation）· MD 数学公式

- **取列**：取 $[\text{用户ID},\ R_{score},\ F_{score},\ M_{score}]$ 四列。
- **白话解释（两步）**：
  1. **二值化**：上一步每个人有了 R/F/M 三个 $1\sim5$ 的分数，但连续分数不好直接分群。这里选一条分数线 $\theta$，把每个分数压成"高/低"两档：分数 $\geq \theta$ 标"高"，否则标"低"。RFM 分群只看"你在每个维度算高还是算低"，不看具体几分。
  2. **群体映射**：每个人现在有 R/F/M 三个"高/低"标记，把这三个标记的组合对应到一个标准名字，就是 8 大群体。为什么是 8：3 个维度 × 各 2 种状态（高/低）→ $2\times2\times2 = 2^3 = 8$ 种组合，每种给一个标准名。
- **$\theta$ 怎么取（业务决策，不写死）**：$\theta$ 是二值化分界，常见三种取法——①固定值（如取 3 = 1~5 中点，或取 4 = 更严只认顶尖档）；②中位数（高低各半、群最均衡，推荐作默认）；③均值（分数偏态时高低比例会偏移）。基座中 $\theta$ 应作为**可调参数**暴露（默认中位数），不写死为某数；前文示例用的 $\theta=3$ 仅为演示中点，并非规则。
- **公式**：
$$R_{lvl} = \mathbf{1}\{R_{score} \geq \theta\},\quad F_{lvl} = \mathbf{1}\{F_{score} \geq \theta\},\quad M_{lvl} = \mathbf{1}\{M_{score} \geq \theta\}$$
$$Segment(u) = Map(R_{lvl}, F_{lvl}, M_{lvl}) \rightarrow \{\text{重要价值}, \text{重要保持}, \text{重要发展}, \text{重要挽留}, \text{一般价值}, \text{一般保持}, \text{一般发展}, \text{一般挽留}\}$$
（重要挽留 ≈ 高 $M$ 但 $R$ 低 $F$ 低，即"流失风险"群体）
- **举例**（设 $\theta=3$）：用户甲 R=5,F=3,M=4 → (高,高,高) → **重要价值**（最近买、买得勤、花得多）；用户乙 R=1,F=2,M=5 → (低,低,高) → **重要挽留**（花得多但很久没来、也不常来，即高流失风险）。
- **输出列**：宽表新增 $[R_{lvl},\ F_{lvl},\ M_{lvl},\ Segment]$；8 群计数 / 占比分布表。



**基座输出**：基座的 RFM 路径（2.1→2.2→2.3）产出每用户一行 RFM 打分宽表 + 8 大群体分布（"用户-分群映射 + 分布"，非 Cohort 类下三角矩阵）。

### 2.4 基座可视化产出（可生成的图表与业务作用）

本步定义"跑完 Base 能直接画什么图、解决什么业务问题"，作为计算层到决策层的桥梁。

- **RFM 8 群分布图（条形 / 饼图）**
  - 数据来源：2.3 输出的 8 群计数 / 占比分布表。
  - 业务作用：一眼掌握用户结构健康度——主力群（重要价值 / 重要保持）占比是否够高、流失风险群（重要挽留 / 一般挽留）是否膨胀；运营据此决定预算倾斜方向。
- **RFM 三维散点图（颜色 = 群体）**
  - 数据来源：2.2 的 $R_{score}/F_{score}/M_{score}$（或 2.1 的 raw）作坐标，2.3 的 $Segment$ 上色。
  - 业务作用：直观看 8 群在 $(R,F,M)$ 空间的分离度；若两群严重重叠，说明 $\theta$ 切点或分箱不合理，需回调控参。
## 第三段：进阶探测层（Advanced Probe）—— 从核心往深里挖

触发：传入字典含指定【进阶可选】列才触发对应分支（基座不变，进阶只在其上叠加维度 / 换指标）。

**说明**：本层仅作用在 Base 的 RFM 分群结果（8 群名，`$Segment$`）之上。K-means 的进阶分析见第三段补充。

### A 渠道 / 类目细分 RFM（探测列：流量来源、商品类目）· MD+1

- **取列**：在 2.1 取列基础上，额外取 $\{\text{流量来源},\ \text{商品类目}\}$ 中存在的列作为维度 $k$。
- 在 2.1 聚合时加维度，按 $(\text{用户ID},\ 维度_k)$ 分组（或 2.3 映射后按维度切分），算各渠道 / 类目的 8 群分布：
$$Segment(u,k) = Map(\dots)\ \text{per 维度 } k$$
- **输出数据**：按渠道 / 类目拆分的 8 群分布对比 → 暴露"某渠道拉来的用户 $F$ 偏低 / 质量差"盲区。

### B 时间动态 RFM（探测列：订单年月）· MD+1

- **取列**：在 2.1 取列基础上，额外取 $\{\text{订单年月}\}$。
- 不再用全局单一基准，改为按 订单年月 滑动窗口重算 $R/F/M$，观察群体随时间的流转迁移：
$$R_{raw}(u, t) = T_t - \max(\text{订单时间}_u \mid \text{订单年月} \leq t)$$
- **输出数据**：群体随时间迁移矩阵（重要价值 → 重要挽留的衰退路径）→ 暴露"价值衰退"盲区。

### C 净毛利净化 RFM（探测列：商品成本、退款金额(可选)、运费(可选)）· MD+2

- **取列与净毛利计算**（在 2.1 取列基础上额外取成本类列；统一规则：**净毛利 = 订单实付金额 − 所取到的成本类列之和**，未取到的项按 0 处理；按实际传入列分三种情况）：
  - **三列全取**（商品成本、退款金额、运费 都传入）：额外取 $\{\text{商品成本},\ \text{退款金额},\ \text{运费}\}$ 三列，净毛利扣除全部三项：
    $$M_{raw}'(u) = \sum(\text{订单实付金额} - \text{商品成本} - \text{退款金额} - \text{运费})_u$$
  - **只取一个**（仅其一传入）：只扣那一项，另两项按 0：
    $$M_{raw}'(u) = \sum(\text{订单实付金额} - \text{商品成本})_u \qquad (\text{仅取到 商品成本})$$
    $$M_{raw}'(u) = \sum(\text{订单实付金额} - \text{退款金额})_u \qquad (\text{仅取到 退款金额})$$
    $$M_{raw}'(u) = \sum(\text{订单实付金额} - \text{运费})_u \qquad (\text{仅取到 运费})$$
  - **取两个**（中间态，任意两项传入）：扣除对应两项、未取到项按 0，例（仅 商品成本 + 运费）：
    $$M_{raw}'(u) = \sum(\text{订单实付金额} - \text{商品成本} - \text{运费})_u$$
- 用 $M_{raw}'$ 替换 2.1 的 $M_{raw} = \sum \text{订单实付金额}$，后续仍走 2.2 分箱打分、2.3 二值化映射，重算 $M_{score}$ 与 $Segment$。
- **输出数据**：净化后的 8 群（剔除"高 $M$ 分但净毛利为负"的虚假价值用户）→ 暴露"看起来重要价值实则亏钱"盲区。

### 进阶可视化产出（可生成的图表与业务作用）

本步定义"跑完 Advanced 各分支能画什么图、深挖什么盲区"，均叠加在 Base 分群结果之上。

- **A 渠道 / 类目细分 → 分组堆叠条形图**
  - 数据来源：A 分支产出的"按渠道 / 类目拆分的 8 群分布"。
  - 图表形态：x 轴 = 渠道（或类目），堆叠段 = 8 群占比。
  - 业务作用：对比各渠道用户结构，识别"某渠道拉来的用户 $F$ 偏低 / 流失群占比高"的低质渠道，优化投放。
- **B 时间动态 → 群体流转桑基图 + 群体占比折线图**
  - 数据来源：B 分支产出的"群体随时间迁移矩阵"。
  - 图表形态：桑基图（节点 = 各期群体，流宽 = 迁移人数）；折线图（x = 时间，y = 各群占比）。
  - 业务作用：看清用户如何从"重要价值"滑向"重要挽留"，定位流失发生的生命周期阶段，提前预警衰退。
- **C 净毛利净化 → 群净毛利矩阵热力图 + 双轴图**
  - 数据来源：C 分支产出的"各群净毛利"。
  - 图表形态：热力图（行 = 8 群，列 = 净毛利指标，色 = 值）；双轴图（柱 = 群人数，线 = 群净毛利总额）。
  - 业务作用：一眼看哪个群"表面 $M$ 高但净毛利为负"，揪出"人数多却亏钱"的虚假价值群，避免误投挽留预算。
