# 用户画像模型 · 三段式算法拆解

> 拆解逻辑（用户定的尺子）：第一段 硬性阻断层 HardBlock（把门）→ 第二段 基座计算层 Base（立核心，最优先）→ 第三段 进阶探测层 Advanced（从核心往深里挖）。
> 下游目的：本拆解即后端（Python / Pandas）代码规格——据此直接生成 `user_profile.py` 计算模块（`validate_input` + `compute_base` + `compute_advanced_a/b/c`）。

---

## 输入约定（原始标准列 ⊕ 上游分群输出，双源拼接）

本模块的输入表 = **原始标准列（用户级）** 与 **RFM / K-means `USER_SEG` 用户级输出宽表** 按 `用户ID` 拼接而成（每用户一行，带分群标签 + 用户属性），**不是**订单流水原始表。不参与"白名单=原生列"铁律——本模块在上游"订单流水 → 用户级"链路的下游，吃的是已处理好的宽表。

**双源职责划分（属性列与分群列各归其源，互不替代）**：
- **源① 原始标准列（画像属性的唯一来源）**：经映射词典归一化后的用户级标准列（用户主数据，或订单流水聚合到用户级的字段）。**全部属性列均取自此处，分群输出里不含任何属性列**：
  - **2.1 分组人数 / 2.2 上游画像列透传**：仅依赖源② 上游分群输出（分组键 + 上游画像列），不依赖源① 任何属性列——只要上游跑通即可产出，**不受源① 缺列影响**。
  - **2.3 数值列均值聚合**：`总消费金额`、`距上次登录天数` 两列**各自独立**——存在则算对应均值列、缺失则该列跳过，**互不影响、也不影响其他步**。
  - **唯一整体 `skipped` 硬门槛**：仅当源② 分组键（`分层`/`簇`）缺失（上游 RFM/K-means 未跑通）时整个模型 skipped；任何源① 属性列缺失都**只跳过对应步/列**，不连坐。
  - 扩展可选（缺失 → 仅跳过该指标）：`年龄`、`收入水平`、`在站时长`、`订阅通知`、`性别`、`所在地区`、`兴趣`、`偏好产品类别`——有则算、无则跳过对应步。
- **源② RFM / K-means 输出（分组键 + 上游画像列的唯一来源）**：提供分组键 `分层`/`簇` 及上游已聚合的画像列（人均净毛利/复购率 或 $M$/$R$）。

**⚠️ 传数纪律**：喂本模块时，**不仅要传 RFM/K-means 的分群输出，也必须把原始标准列一并传入**——总消费、距登录天数、年龄、订阅率等属性维度全部来自原始标准列；只传分群输出、不带原始标准列 → 仅导致 2.3/2.4/2.5/2.6 对应列缺省跳过，**不会**整体 skipped（整体 skipped 仅当分组键缺失）。

**两套上游，两套分组键（均来自源②）**：
- RFM 路径 → 分组键 = `分层`（列值 = RFM 8 群名，如"高价值核心客户""流失预警高价值客户"）
  - RFM 输出列：`分层 ｜ 人数 ｜ 占比 ｜ 人均净毛利 ｜ 复购率` ——人均净毛利 = `profit.sum() / 人数`（格式 `,.2f`）；复购率 = $F_{raw} \geq 2$ 的人数占比（格式百分比）
- K-means 降级路径 → 分组键 = `簇`（列值 = 聚类簇编号）
  - K-means 输出列：`簇 ｜ 人数 ｜ 占比 ｜ M ｜ R` ——$M$ 行值 = 该簇 $M$ 的均值；$R$ 行值 = 该簇 $R$ 的均值

**运行时序**：RFM 能跑 → 用 `分层`；RFM `skipped` → 降级 K-means 用 `簇`；二者都 `skipped` → 本模块 `skipped`。

## 第一段：硬性阻断层（HardBlock）—— 输入数据校验

- **校验对象**：Pandas DataFrame 列名
- **必备列集（仅一层：分组键，缺失 → skipped）**：
  - **① 分组键**（主路径优先）：$C_{core}^{(1)} = \{\text{分层}\}$（RFM 输出）；若 `分层` 缺失检查 $\{\text{簇}\}$（K-means `USER_SEG` 输出）。选定后记为 $g \in \{\text{分层},\ \text{簇}\}$。
  - **② 核心属性列（已降级为「按列独立」）**：`总消费金额`、`距上次登录天数` 不再作为 HardBlock 门槛——二者各自独立进入 2.3，存在则算对应均值列、缺失则该列跳过，**绝不触发整体 skipped**，也不影响 2.1/2.2/2.4/2.5/2.6。
- **阻断**：仅当（分组键 `分层`/`簇` 均缺失）→ `return {"status":"skipped"}`（跳过非报错）。属性列缺失**不阻断**，仅跳过对应列。
- **标注**：`MD 算法阻断`

## 第二段：基座计算层（Base Calculation）—— 模型最核心分析

**目标**：用户级宽表（含分群标签列 $g$ + 上游画像列 + 用户属性列）→ 每个分群一行画像（上游列透传 + 数值均值 / 订阅率 / 主导品类 / 类别占比）。

### 2.1 分组与人数（Grouping & Size）· MD 数学公式

- **取列**：取分组键 $g$（`分层` 或 `簇`），必要时也取 `用户ID` 作回贴。
- 按 $g$ GroupBy，统计每群人数：
$$n_s = \bigl|\{u \mid g(u) = s\}\bigr|$$
- **白话**：每个分群有多少人——即上游输出的 `人数` 列（上游已算，本步复算保一致）。
- **数据形状**：临时表 $[g,\ n_s]$（每群一行，列 $g$ 的实际列名为 `分层` 或 `簇`）。

### 2.2 上游画像列透传（Pass-through）· MD 数学公式

- **取列**：取上游输出列中已存在的画像列，按 $g$ GroupBy 取唯一值直接透传（上游已按分群聚合，本模块不重复算）。
  - **RFM 路径**（$g = \text{分层}$ 时）：透传 `人数`、`占比`、`人均净毛利`、`复购率`
  - **K-means 降级路径**（$g = \text{簇}$ 时）：透传 `人数`、`占比`、$M$、$R$
- **白话**：这些列在上游模块（RFM/K-means）已经按分群算好了——人均净毛利/复购率 来自 RFM（`profit.sum()/人数`, `F_raw>=2 占比`），$M$/$R$ 来自 K-means 的簇中心均值——画像模块直接接过来，不重复劳动。`人数`/`占比` 可与 2.1 复算结果交叉校验防漂移。
- **数据形状**：宽表新增 $[\text{人数},\ \text{占比},\ \text{人均净毛利},\ \text{复购率}]$（RFM）或 $[\text{人数},\ \text{占比},\ M,\ R]$（K-means）。

### 2.3 数值列均值聚合（Numeric Aggregation）· MD 数学公式

- **两列各自独立（不再「核心必算」）**：`总消费金额`、`距上次登录天数` —— 每群算术均值，**但各自独立判定**：列存在则算对应均值并作为基座表一列输出，列缺失则该列跳过（基座表不出现该列），互不影响：
$$\bar{x}_s = \frac{1}{n_s}\sum_{u \in S_s} x_u \quad \text{（仅当 } x = \text{总消费金额 / 距上次登录天数 该列存在时）}$$
- **扩展可选（缺失 → 跳过该列）**：`年龄`、`收入水平`、`在站时长` —— 同样算术均值，仅当对应列存在时才加列。
- **白话**：对每群人，把消费力 / 活跃度（按列独立）和年龄 / 收入 / 在站时长（扩展）求平均——得出"这群人长啥样"。某列缺失只导致该维度画像缺省，不连坐其他维度。
- **数据形状**：宽表新增 $[\overline{\text{总消费}}_s,\ \overline{\text{距上次登录天数}}_s]$ 中**实际存在的列**（两列可独立缺失其一），加 $[\overline{\text{年龄}}_s,\ \overline{\text{收入}}_s,\ \overline{\text{在站时长}}_s]$ 中实际存在的列。

### 2.4 订阅率（Subscription Rate）· MD 数学公式 · 【扩展可选】

- **探测列**：`订阅通知`（扩展可选，缺失 → **跳过本步**，不影响基座其他指标）。
- **取列**：取 $\{\text{订阅通知}\}$；按 $g$ GroupBy，每群算"订阅通知 = True"的比例：
$$\text{订阅率}_s = \frac{1}{n_s}\sum_{u \in S_s} \mathbf{1}\bigl(\text{订阅通知}_u = \text{True}\bigr)$$
- **白话**：这群人里订阅通知的占多少——衡量营销触达潜力。
- **数据形状**：若 `订阅通知` 存在，宽表新增 $[\text{订阅率}_s]$（取值 $[0,1]$）；缺失则该列不出现。

### 2.5 主导品类（Dominant Category）· MD 数学公式 · 【扩展可选】

- **探测列**：`偏好产品类别`（扩展可选，缺失 → **跳过本步**）。
- **取列**：取 $\{\text{偏好产品类别}\}$；按 $g$ GroupBy，每群选出现次数最多的类目（众数）：
$$\text{主导品类}_s = \arg\max_c\ n_{(s,c)} \quad\text{其中 } n_{(s,c)} = \bigl|\{u \mid g(u)=s,\ \text{偏好产品类别}_u=c\}\bigr|$$
- **白话**：这群人最喜欢的品类是哪个（出现次数最多的）——直接指导选品与品类运营。
- **数据形状**：若 `偏好产品类别` 存在，宽表新增 $[\text{主导品类}_s]$（取值 = 类目中文键）；缺失则该列不出现。

### 2.6 类别占比扩展（Categorical Distribution）· MD 数学公式 · 【扩展可选】

- **探测列**：`性别`、`所在地区`、`兴趣`（均扩展可选，各列独立缺失 → 仅跳过该列，不阻断）。
- **取列**：取上述列中**存在的**列；按 $g$ GroupBy，每群对每个类别列算**占比分布**（每个取值占多少比例）。
- **公式**：对类别列 $C$ 取值 $v$：
$$\text{占比}(s, C=v) = \frac{\bigl|\{u \mid g(u)=s,\ C_u=v\}\bigr|}{n_s}$$
- **白话**：这群人的性别分布（男/女/未知各占多少）、地区分布（华东/华南/...各占多少）、兴趣分布——**只算上传表里实际存在的列**。
- **数据形状**：宽表新增 $[\text{性别分布}_s,\ \text{地区分布}_s,\ \text{兴趣分布}_s]$ 中实际存在的列（每列以字典/JSON 存多档占比）。

**基座输出**：分群画像表（每群一行），经 2.7 渲染为「群画像总览表」（四区块 + 颜色编码）。**必出列**（仅依赖上游分组键，恒有）：$[g,\ \text{人数},\ \text{占比},\ \text{上游画像列}^*]$（$g$ 实际列名 = `分层` 或 `簇`；`上游画像列*` = `人均净毛利+复购率` 或 $M+R$）。**2.3 按需列**（列存在才出现）：$[\overline{\text{总消费}}_s,\ \overline{\text{距上次登录天数}}_s]$（二者独立，可只出其一或都缺）。**其他可选列（对应上传表存在的扩展列才出现）**：$[\overline{\text{年龄}}_s,\ \overline{\text{收入}}_s,\ \overline{\text{在站时长}}_s,\ \text{订阅率}_s,\ \text{主导品类}_s,\ \text{性别分布}_s,\ \text{地区分布}_s,\ \text{兴趣分布}_s]$。

### 2.7 基座可视化产出（计算层 → 决策层桥梁）

- **群画像总览表（替代原雷达图 / 订阅率条形图 / 主导品类对比表三图合一）**：一张 HTML 表格，行 = 分群；列分四区块——基础信息区（分群 / 人数 / 占比）· 上游画像区（RFM 的 M/R 即消费力 / 近度，或 K-means 的 M/R）· 核心属性区（总消费 / 距上次登录）· 扩展属性区（订阅率 / 年龄 / 收入 / 在站时长 / 主导品类 / 性别 / 地区 / 兴趣）。各区块的列按上传表实际存在动态显示，缺失列不渲染、不报错。
- **颜色编码三件套**（后端只传数据 + 颜色元数据，前端按元数据上色；`chart_config.kind = seg_profile_overview`）：
  - 数值列单元格背景加半透明进度条，宽度 = 该群在全部群中的相对排名 `rank`（0~100%）。
  - 颜色：绿（高于群间均值 `direction=good`）/ 黄（持平 `equal`）/ 红（低于群间均值 `bad`）。
  - 数值文字用 绿 / 灰 / 红 标注方向；百分比用同色系 badge；品类 / 分类用蓝色 tag。
  - **不上色约定**：近度类列（距上次登录 / 上游 R）、年龄 / 收入 / 在站时长等中性列只显示数值与进度条、不染方向色（避免"低近度 = 红"这类反直觉误读）。
- **业务作用**：8 个 RFM 分群在一张表里横向比所有维度；高价值群绿多、挽留群红多，一眼可辨；群 × 品类 / 群 × 营销触达（订阅率）等信息集中呈现，替代原分散的三张图。

## 第三段：进阶探测层（Advanced Probe）—— 从核心往深里挖

触发（入口契约）：每个分支**独立判断**——仅当自身**探测列**存在于输入时才调用对应 `compute_advanced_*`，多支可并存。各支探测列均为 Base 已用列的子集，故入口判断 = 对该列做 `in df.columns` 校验（详见各支「入口 / 触发判断」）。基座不变，进阶只在其上叠加权重 / 加维度 / 换分组粒度。

### A 加权画像（探测列：总消费金额）· MD+1

- **入口 / 触发判断**：权重列 `总消费金额` 属 2.3 按需列——**仅当 2.3 实际算出了 `总消费金额` 均值（即 `总消费金额` 列存在于输入）时 A 才跑**，否则跳过（A 无额外门槛但依赖 2.3 该列存在）。
- **算法推导变更**：把 2.3 的算术均值改为**消费加权均值**（权重 = 该用户的总消费金额 $M_u$）：
$$\bar{x}_s^{(w)} = \frac{\sum_{u \in S_s} x_u \cdot M_u}{\sum_{u \in S_s} M_u}$$
- **数学公式变更**：仅 2.3 的分母分子加权重。
- **白话**：忽略低消费噪声、聚焦"高价值子群视角"的画像。
- **输出数据**：加权画像表（与基座并列）→ 暴露"未加权画像被几个极端低消费用户拉偏、真正高价值画像该看加权"盲区。

### B 群内类别分布对比（探测列：性别, 所在地区, 兴趣）· MD+1

- **入口 / 触发判断**：B 是 2.6 的深化，依赖 `性别 / 所在地区 / 兴趣` 三类别列（与 2.6 同源）。**2.6 跑通（即这三列中至少一个存在于输入）则 B 可跑**，且**逐列独立触发**——某列存在才做该列群间对比，缺失列跳过。代码入口：`compute_advanced_b(df, base_result)` 在 **2.6 返回运行成功后**调用，内部 `trigger = [c for c in ["性别","所在地区","兴趣"] if c in df.columns]`，`if trigger:` 才跑。
- **算法推导变更**：在 2.6 基础上，对每个类别列做"群间分布对比图"。
- **数学公式变更**：占比公式不变，输出形态从"每群一张分布"变成"群 × 取值 矩阵"。
- **输出数据**：群 × 性别 / 群 × 地区 / 群 × 兴趣 的占比热力图 → 暴露"某群偏男/某群集中某地区/某群兴趣高度同质"盲区。

### C 区域 × 客户交叉引用（探测列：所在地区）· MD+2

- **入口 / 触发判断**：C 把画像指标重算到双维 $(g \times \text{所在地区})$ 粒度，需 `所在地区` 作为第二分组轴（硬性要求，缺失则无第二维）。**仅当 `所在地区` 存在于输入则 C 可跑**（内部各画像指标按列存在与否在该双维下独立重算，缺列只跳过对应指标），否则整支跳过。
- **算法推导变更**：把分组从单维（$g$）变为双维（$g \times \text{所在地区}$）：
$$n_{(s,r)} = \bigl|\{u \mid g(u)=s,\ \text{所在地区}_u=r\}\bigr|$$
对每个 $(s, r)$ 组合重算 2.3 / 2.4 / 2.5 / 2.6 的画像指标。
- **数学公式变更**：分组键由 1 维变 2 维，所有聚合公式的分母换成 $n_{(s,r)}$。
- **白话**：区域运营视角——"华东地区的高价值核心客户"画像独立看；指导不同地区对不同群的差异化营销。
- **输出数据**：群 × 地区 的双维画像表 + 热力图 → 暴露"某群在某地区集中/稀疏"盲区。

### 进阶可视化产出（叠加在 Base 之上）

- **A 加权画像对比图**：每群画两张雷达图（未加权 vs 加权），叠加显示。业务作用：识别"被低消费噪声拉偏"的群，调整画像口径。
- **B 群内分布热力图**：x = 群，y = 类别取值，色 = 占比。业务作用：定位某群在某类别上的极化（如"高价值核心客户 90% 男性"）。
- **C 群 × 地区 双维画像热力图**：行 = 群（$g$），列 = 所在地区，色 = 各画像指标。业务作用：区域运营做"哪个地区重点投哪个群"的精细化决策。

## 与现有模块的衔接（强依赖 + 多模型协同）

### 与 RFM / K-means 的依赖关系

- **强依赖**：本模块必须**先**跑 RFM 或 K-means `USER_SEG`，拿到分群标签列（`分层` 或 `簇`）+ 上游画像列（人均净毛利/复购率 或 $M$/$R$）。
- **降级链**（与 RFM 文档一致）：RFM 能跑 → 用 `分层`；RFM `skipped` → 降级 K-means 用 `簇`；二者都 `skipped` → 本模块 `skipped`。
- **本模块的输入表**：`原始标准列` ⊕ `RFM/USER_SEG 用户级输出` **按 `用户ID` 拼接的双源宽表**（每用户一行，含分群标签 + 上游画像列 + 用户属性列），**不是**订单流水原始表。属性列源自原始标准列，分群标签 / 上游画像列源自 RFM/K-means 输出。
- **本模块的输出表**：被"区域运营 / 营销策略"模块消费（截图明确："输出表被区域×客户交叉引用"）。

### 与 CLV 的关系（独立但可联合）

- **CLV 不依赖本模块**——CLV 是独立模型（白名单是订单流水原生列），不需要先画像。
- **本模块不依赖 CLV**——基座只消费 RFM/USER_SEG 的分群标签列（`分层`/`簇`）+ 上游画像列。

## 交叉校验结论

- **C_core 分组键（`分层` / `簇`）**：`分层` 为 RFM 输出分群标签列；`簇` 为 K-means `USER_SEG` 输出聚类标签列。两列均不在映射词典原生列区（属上游模块派生输出）。
- **C_core 核心属性列（`总消费金额` / `距上次登录天数`）**：画像灵魂维度，来自传入的源① 原始标准列；**现已降级为「按列独立」**——各自独立进入 2.3，缺失则该列跳过、不触发整体 skipped；均已在 `映射词典.md` 原生列区。
- **扩展可选列（`年龄` / `收入水平` / `在站时长` / `订阅通知` / `性别` / `所在地区` / `兴趣` / `偏好产品类别`）**：有则算、无则跳过对应步；均已存在于 `映射词典.md` 原生列区。
- **词典无需扩充**；`分层`/`簇` 两列为上游模块（RFM/K-means）输出，本模块作为下游消费方直接读取；属性列遵循「2.1/2.2 仅依赖分组键；2.3 两列按列独立、缺则跳过；扩展可选缺失 → 跳过该指标」的新铁律（仅分组键缺失 → 整体 skipped）。
