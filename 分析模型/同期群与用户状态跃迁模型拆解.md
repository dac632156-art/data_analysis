# 同期群与用户状态跃迁模型 · 三段式算法拆解

> 拆解逻辑（用户定的尺子）：第一段 硬性阻断层 HardBlock（把门）→ 第二段 基座计算层 Base（立核心，最优先）→ 第三段 进阶探测层 Advanced（从核心往深里挖）。
> 下游目的：本拆解即**后端（Python/Pandas）代码规格**——每步"取列→计算→输出列"= 函数 I/O 契约，数据形状 = DataFrame schema。
> 代码架构约定：HardBlock → 输入校验函数 `validate_input()`；Base → 单一封装函数 `compute_base(df)`；Advanced → 每个衍生各一个独立封装函数 `compute_advanced_a/b/c(df, base_result)`，由传入字典是否含该分支【进阶可选】列决定调用哪些、可并存。

> **大白话**：把"同期群分析"拆成三关。第一关先查数据能不能用（不合格直接打回）；第二关算最要紧的——哪些人留下来了、每人花了多少；第三关是加分项，从渠道、时间趋势、真赚多少钱等角度再深挖。下面每一节先写专业做法，再跟一句人话。

## 第一篇：硬性阻断层（HardBlock）—— 输入数据校验

- 校验对象：Pandas DataFrame 列名与取值合理性

> **大白话**：第一关＝"数据体检"。还没开始算，先确认表里有必填的列、没有明显脏数据（比如下单时间跑到未来）。过不了就直接跳过，不浪费算力。
- 必备列集（硬门槛，缺一不可）：$C_{core} = \{\text{用户ID},\ \text{订单时间},\ \text{订单实付金额}\}$（**大白话**：这三列缺一不可——用户ID 是"这是谁"，订单时间 是"他啥时候买的"，订单实付金额 是"他花了多少钱"）
  - 用户ID：分组主键（定位"哪个用户"）（**大白话**：拿订单归到具体某个人）
  - 订单时间：算 cohort 锚点（首单月）与月偏移 $j$（**大白话**：靠它才能算"某人第几个月买的"）
  - 订单实付金额：算各 cohort 格子的营收 $R_{ij}$ 与 ARPU 矩阵。**你原图基座即产出 ARPU 下三角热力图，故金额是必备列**（非"有则增强"）；缺失则基座 ARPU 产出无法成立。（**大白话**：要画"每人平均花多少"的图，这列必须有）
  - 注：你记忆中的"基层两列"是**留存**的最小列（用户ID+订单时间）；但本模型基座按你原图口径同时出"留存率矩阵 + ARPU 矩阵"两产出，所以金额必须进 $C_{core}$。仅"订单ID"为条件列（控重增强）。（**大白话**：只算"谁还回来买"两列就够；但咱还要算"花了多少钱"，所以金额也得必备）
- 条件列（存在才使用，缺失则优雅降级、不阻断）：
  - `订单ID`：存在则 $R_{ij}$ 按 订单ID 去重计数（一笔订单拆多行 SKU 时避免金额重复计）；**缺失则假定"一行一单"，跳过金额去重并记质量提示**。（**大白话**：这是"单号"，防止一笔单拆成多行时被重复算钱）
  - `订单状态`：若存在，须先按白名单过滤有效订单再算（见执行顺序 ④）。（**大白话**：这单到底成没成，"已取消/已退款"的不能算数）
  - `退款完成日期` / `退款金额`：仅 Advanced C 用到，HardBlock 不强制。（**大白话**：这俩只有进阶 C 算"真正赚多少"时才用，平时不管）
- 阻断：若 $C_{core} \not\subset \text{原始列}$ → `return {"status":"skipped","reason":"missing_core_columns","missing":[缺失列]}`（跳过非报错）（**大白话**：缺了那三列必备，程序直接说"这数据我算不了"，跳过不报错）
- 标注：`MD 算法阻断`

### HardBlock 执行顺序（`validate_input()` 内部）

> **大白话**：下面 5 步是进门前的固定流水线：先看列齐不齐 → 定个统一时区 → 踢掉未来时间的怪数据 → 只留真正成交的订单 → 同一笔单多行只算一次。顺序不能乱。

1. **列存在性校验**：检查 $C_{core}$ 三列（用户ID, 订单时间, 订单实付金额）齐全，缺则 `skipped`。（**大白话**：先点名，三列少一个就打回）
2. **时区与月份边界常量（写死默认，可配）**：
   - `TZ = "Asia/Shanghai"`  # 即北京时间 UTC+8，无夏令时（Python `zoneinfo` 标准标识符；很多库不认字符串 "Beijing"，故用此名）（**大白话**：统一用北京时间算"月"，免得有人用别的时区算出不同结果）
   - 月份边界 = 该时区下的**自然月**：每月 1 日 00:00:00 至月末 23:59:59.999999（**大白话**："一个月"就按日历自然月算）
   - 所有"月"的计算（首单月、订单月、月偏移、最小观察期）均在 `TZ` 下取自然月，统一口径（**大白话**：所有跟"月"有关的都按这个标准来，口径一致）
3. **未来时间校验**：
   - 计算 `max(订单时间)` 与后端运行日 `today`。（**大白话**：看看最晚的下单时间，跟"今天"比）
   - 先把 `订单时间 > today + 容差` 的行**过滤掉**（容差 `FUTURE_TOLERANCE` 默认 1 天，防时钟漂移），并计 `future_rows`。（**大白话**：把"下单时间比今天还晚"的离谱数据先删掉）
   - 若 `future_rows / total > FUTURE_SKIP_RATIO`（默认 5%）→ `return {"status":"skipped","reason":"future_order_time_suspected"}`（数据整体损坏，疑似时钟错误或刷单）。（**大白话**：要是未来订单占比太高，说明整张表时间都错了，直接跳过）
   - 注：cohort 锚点月 $Cohort\_Month(u) = m(\min(\text{订单时间}_u))$ 在 2.1 才计算；因锚点 = 最早 订单时间，本步已保证所有 订单时间 $\le today$，故 $Cohort\_Month \le today$ **自动成立**，无需在 HardBlock 单独校验。真正拦截"未来获客月不进矩阵"的是 2.4 用 $m(today)$ 做的最小观察期 / 合法 $j$ 范围。
4. **订单状态过滤（条件强制）**：若 `订单状态` 列存在，执行白名单保留 `status ∈ STATUS_WHITELIST`（默认 `{已完成, 已支付}`），剔除 `{已取消, 已退款, 已关闭}` 等无效订单，计 `filtered_rows`。若不存在该列，跳过此步、不打断。（**大白话**：只留"成了的单"，取消/退款的不算钱）
5. **Nunique(订单ID) 控重**：在第 4 步过滤**之后**，所有聚合以 `Nunique(订单ID)` 去重计数（避免一行多 SKU 导致订单数被放大）。此步是聚合纪律，不在 HardBlock 返回，但 HardBlock 须保证 订单ID 列已就绪。（**大白话**：一笔单拆成多行商品时，计数只算一次，别被放大）
- **返回**：校验通过则原样传出（已过滤无效订单、已剔除未来时间行）的 DataFrame，供 Base 使用；附 `future_rows` / `filtered_rows` 计数供后端监控异常。（**大白话**：体检通过，把清理好的表交给下一关，并附带"删了多少行"的记录）

## 第二段：基座计算层（Base Calculation）—— 模型最核心分析

> **大白话**：第二关＝"算核心"。把每笔订单归到"某人第几个月买的"，统计每个组合里有多少人回来买、花了多少，最后画成两张三角形热力图（一张看留存、一张看花钱）。

**目标**：流水订单明细表 → 锁定每用户首单月（cohort 锚点）→ 算每笔订单距首单的月偏移 $j$ → 二维聚合出每 (cohort月 $i$, 偏移 $j$) 格子的用户数 $U_{ij}$ 与营收 $R_{ij}$ → 比率化得留存矩阵 $Retention_{ij}$ 与 ARPU 矩阵 $ARPU_{ij}$（两张**下三角矩阵**）。

> **大白话**：一句话——把订单按"谁、哪个月第一次来、之后第几个月又买了"分堆，数每堆有多少人、花了多少钱，再换算成"留存比例"和"人均花费"。

### 2.1 同期群锚点锁定 Cohort_Month · MD 数学公式

> **大白话**：给每个人找一个"入群月"——就是他第一次下单的那个月。后面所有分析都拿这个月当地铁起点。

- **取列**：从（已过滤的）原始表取 $C_{core}$ 三列 $\{\text{用户ID},\ \text{订单时间},\ \text{订单实付金额}\}$；若 `订单ID` 存在则一并取（供后续金额去重控重）。（**大白话**：抓这三列，有单号也一起抓）
- **推导逻辑**：对每个用户，取其所有订单中**最早**的 订单时间，截取其所属自然月（在 `TZ` 下），作为该用户的 cohort 锚点月 $Cohort\_Month(u)$。同一用户所有订单共享此锚点。（**大白话**：找这个人最早的订单，截出它的"年-月"，这就是他的入群月）
- **公式**（整数月索引，见第 8 点约定）：
  $$m(t) = \text{year}(t)\times 12 + \text{month}(t)$$
  $$Cohort\_Month(u) = m\big(\min_{o \in orders(u)} \text{订单时间}_o\big)$$
  （**大白话**：把日期变成"第几个年-月"的数字，比如 2026年7月＝2026×12+7；取每人最早订单的这个数字）
- **数据形状**：为每行（每笔订单）打标 `Cohort_Month`（整数月索引）；输出仍为每行一笔订单的明细表，新增 `Cohort_Month` 列。
- **复杂度**：$O(n)$（$n$ = 过滤后订单行数）。
- **输出列**：明细表新增 $[\text{Cohort\_Month}]$。

### 2.2 相对跨度 Index_j（月偏移）· MD 数学公式

> **大白话**：算"这笔单距离他第一次下单过了几个月"。首单当月是 0，过 1 个月是 1，过 2 个月是 2……

- **取列**：取 2.1 输出中的 $\{\text{用户ID},\ \text{Cohort\_Month},\ \text{订单时间}\}$。
- **推导逻辑**：每笔订单自身的自然月（同 `TZ`）减去其 cohort 锚点月，得整数月偏移 $j$。$j=0$ 即首单当月，$j=1$ 即首单后第 1 个月，依此类推。（**大白话**：这笔单的月份 减 他的入群月＝间隔月数）
- **公式**（用户指定整数法，不用 PeriodIndex）：
  $$Order\_Month(o) = m(\text{订单时间}_o)$$
  $$Index\_j(o) = Order\_Month(o) - Cohort\_Month(u(o))$$
  （**大白话**：用上面那个"年-月数字"相减，直接得整数月差）
- **数据形状**：每行新增 `Index_j`（非负整数）。
- **复杂度**：$O(n)$。
- **输出列**：明细表新增 $[\text{Index\_j}]$。

### 2.3 二维聚合 $U_{ij}$ / $R_{ij}$ · MD 数学公式

> **大白话**：按"入群月 × 隔了几个月"把订单分进一个个格子里，数每格有多少人回来买（U）、他们总共花了多少钱（R）。

- **取列**：取 $\{\text{Cohort\_Month},\ \text{Index\_j},\ \text{用户ID},\ \text{订单实付金额}\}$（金额已为 $C_{core}$ 必备）；若 `订单ID` 存在则一并取（用于 $R_{ij}$ 去重控重）。
- **聚合逻辑**：按 $(\text{Cohort\_Month}=i,\ \text{Index\_j}=j)$ 分组：
  - $U_{ij}$ = 该格子内 **去重用户数**（`Nunique(用户ID)`）；因一笔订单可能拆多行，用户数须以用户维度去重。（**大白话**：这格里有多少**不同**的人，同一个人买多次只算一个）
  - $R_{ij}$（必备，金额已进 $C_{core}$）：对去重订单的 订单实付金额 求和。若 `订单ID` 存在，先 `Nunique(订单ID)` 控重（同一订单多行只计一次）；若 `订单ID` 缺失则假定一行一单直接求和，并记质量提示。（**大白话**：这格所有人花的钱加总，同一笔单多行只加一次）
- **公式**：
  $$U_{ij} = \big|\{u : Cohort\_Month(u)=i,\ \exists o\ \text{s.t.}\ Index\_j(o)=j\}\big| = \text{Nunique}(\text{用户ID})$$
  $$R_{ij} = \sum_{o \in (i,j)\ \text{组}} \text{订单实付金额}_o\ \ (\text{按 订单ID 去重后求和，若 订单ID 存在})$$
- **数据形状**：长表 $[\text{Cohort\_Month},\ \text{Index\_j},\ U_{ij},\ R_{ij}]$，每 $(i,j)$ 一行。
- **复杂度**：$O(n)$。
- **输出列**：$[\text{Cohort\_Month},\ \text{Index\_j},\ U_{ij},\ R_{ij}]$。

### 2.4 比率与下三角矩阵（Retention / ARPU + 置信区间 + 最小观察期）· MD+1 数学公式

> **大白话**：把上面数出的人数变成能看的指标——"留存率"（回来的人占首月比例）和"人均花费 ARPU"；再标出百分比靠不靠谱；最后拼成左上满、右下空的三角表。

- **取列**：取 2.3 输出的 $[\text{Cohort\_Month},\ \text{Index\_j},\ U_{ij},\ R_{ij}]$。
- **比率推导**：
  - 留存率：$Retention_{ij} = U_{ij} / U_{i0}$（$U_{i0}$ = cohort $i$ 在 $j=0$ 的用户数 = 该 cohort 总规模，因首单必在 $j=0$）。
  - 客单价：$ARPU_{ij} = R_{ij} / U_{ij}$。
- **公式**：
  $$Retention_{ij} = \frac{U_{ij}}{U_{i0}}$$
  $$ARPU_{ij} = \frac{R_{ij}}{U_{ij}}$$
- **95% 置信区间（Wilson，比例专用，写死默认 `CONFIDENCE=0.95`）**：
  $$z = \Phi^{-1}(1-\alpha/2),\quad \hat{p} = Retention_{ij},\quad n = U_{i0}$$
  $$CI_{ij} = \frac{\hat{p} + z^2/(2n) \pm z\sqrt{\hat{p}(1-\hat{p})/n + z^2/(4n^2)}}{1 + z^2/n}$$
  （小样本比正态近似稳；大样本二者趋同。$\alpha=0.05$ 可配。）
- **最小观察期过滤（解决"右下角近期 cohort 误读"）**：
  - 问题：下三角矩阵行 $i$=获客月、列 $j$=月偏移。近期 cohort（如 2026-07）只收集到 $j=0,1,2$，$j=3,4\ldots$ 尚在未来、无数据，矩阵填 `NaN`。若照原样画，右下角整片稀疏，业务会误读为"近期用户留存差"。（**大白话**：才来一两个月的新客，后面月份还没发生，别拿空白格当"留存差"）
  - 解法（A 为主 + B 兜底，写死 `MIN_OBSERVATION_MONTHS`，默认 6、可配）：
    - (A) 仅让 `m(today) - Cohort_Month(i) ≥ MIN_OBSERVATION_MONTHS` 的 cohort 进基座矩阵（未成熟 cohort 整行不进图）。（**大白话**：默认让至少满 6 个月的 cohort 才进图，太嫩的不算）
    - (B) 其余 $(i,j)$ 仍可能存在的 `NaN` 显式标记为**"未观测"**而非 "0 留存"（图上用灰块/斜线区分），避免被误读为"留存为 0 / 质量差"。（**大白话**：空白就标"还没数据"，别标成"0"，否则看起来像人都跑光了）
- **下三角矩阵形态**：对每个纳入的 cohort $i$，其 $j$ 取值范围 $0 \le j \le m(today) - Cohort\_Month(i)$；矩阵 $M[i][j]$ 在该范围内为值、范围外为"未观测"。输出 `Retention 矩阵` 与 `ARPU 矩阵` 两张下三角。（**大白话**：表格左上是"老 cohort 的长历史"很满，右下是"新 cohort 还没长出来"留空，所以叫下三角）
- **数据形状**：两张 $(|i| \times |j|)$ 下三角矩阵（行=cohort月，列=月偏移），含值 / 置信区间 / "未观测"标记。
- **复杂度**：建索引 $O(n)$ + 矩阵填充 $O(|i|\cdot|j|)$；总 **$O(n + |i|\cdot|j|)$**（$|i|$=cohort 月数，$|j|$=最大偏移）。删除原 "N/A" 噪声，写准如上。
- **输出列 / 结构**：`Retention[i][j]`、`Retention_CI_lower[i][j]`、`Retention_CI_upper[i][j]`、`ARPU[i][j]`、观测状态标记。

**基座输出**：留存率下三角矩阵 + ARPU 下三角矩阵（均含 95% CI 与"未观测"标注）。Cohort 类规范输出。

### 2.5 基座可视化产出（可生成的图表与业务作用）

> **大白话**：把前面算出的两张三角数字表，画成颜色深浅的"热力图"，业务一眼就能看懂。

**📐 月偏移 j=0 口径总原则（重要，避免误读为 bug）**：
- **留存率相关 → 部分去 j=0**：整体留存率卡片去 $j=0$（避免虚高近 100%）；**留存率下三角热力图保留 $j=0$ 列**（用户要求，主对角线恒=1 作基线参照，与 ARPU 图口径对齐，便于同图对比）。$j=0$ 是 cohort 自身基线，留存率恒等于 1（100%），画出来是一条满值列，但作为参照有意义。
- **跟留存率无关的（金额类）→ 留 j=0**：ARPU 下三角热力图、净毛利 ARPU 下三角热力图、平均客单价卡片、总营收卡片、明细行。因为 $j=0$ 即"首单当月人均消费 / 净毛利"，反映拉来的这批新客质量，是真实且有分析价值的指标。
- 进阶 A（渠道 M1 留存堆叠）、进阶 B（质量趋势折线）本质留存率类，但本来就只画 $j\ge1$，不涉及 $j=0$ 列，无需特殊处理。
- 数据同源：导出 analysis package 的 json 包（charts + summary_cards）与前端热力图均读取后端打包结果，故改后端口径后 json 包与前端自动同步含/去 j=0，无需单独改。

- **留存率下三角热力图**
  - 数据来源：2.4 的 `Retention[i][j]`（配 `CI` 与"未观测"灰块）。
  - 业务作用：一眼看各获客月用户的留存衰减曲线——主对角线（$j=0$）恒为 1，向右下看衰减快慢；识别"哪批 cohort 留存断崖式下跌"。（**大白话**：颜色越深＝留得越好，一眼看出哪个月拉来的人跑得最快）
  - **可视化口径**：保留 $j=0$ 列（主对角线恒=1，作基线参照，与 ARPU 图对齐），热力图画 $j=0\sim11$。
- **ARPU 下三角热力图**（金额已为 $C_{core}$ 必备，基座必出）
  - 数据来源：2.4 的 `ARPU[i][j]`。
  - 业务作用：看各 cohort 随时间的变现能力，配合留存识别"留存还在但不再花钱"的沉默化盲区。（**大白话**：看哪批人舍得花钱、哪批人留是留了但不掏钱）
  - **可视化口径**：保留 $j=0$ 列（$j=0=$ 首单当月客单价，反映获客质量，热力图画 $j=0\sim11$）。

## 第三篇：进阶探测层（Advanced Probe）—— 从核心往深里挖

> **大白话**：核心算完还不够，再从不同角度深挖——按渠道/类目看、看质量随时间变化、扣掉成本看真赚多少。这些是加分项。

触发：传入字典含指定【进阶可选】列才触发对应分支（基座不变，进阶只在其上叠加维度 / 换指标）。

> **大白话**：只有当你额外提供了某些列，才做对应的进阶分析；没提供就只出核心那两张图。

### A 渠道 / 类目维度升维（探测列：流量来源、商品类目）· MD+1

> **大白话**：A＝把留存表按"从哪来的（渠道）"或"买的啥（类目）"拆开看，找哪路人流存差。

- **取列**：在 2.1/2.2 取列基础上，额外取 $\{\text{流量来源},\ \text{商品类目}\}$ 中存在的列作为维度 $k$。
- **升维聚合**：按 $(\text{Cohort\_Month},\ \text{维度}_k,\ \text{Index\_j})$ 三维分组，重算每渠道 / 每类目的 $U_{ij}$、$R_{ij}$、$Retention_{ij}$、$ARPU_{ij}$，即 Base 矩阵沿维度 $k$ 裂变为多张子矩阵。
- **公式**：
  $$Retention_{ij}^{(k)} = \frac{U_{ij}^{(k)}}{U_{i0}^{(k)}}$$
- **输出数据**：按渠道 / 类目拆分的留存 / ARPU 子矩阵 → 暴露"某渠道拉来的用户留存偏低 / 某类目复购差"盲区。

### B 同期群质量趋势（探测列：事件时间、行为类型）· MD+1

> **大白话**：B＝看不同月份拉来的人，质量是不是在变好/变差（只是看趋势，别当因果证明）。

- **取列**：在 2.1 取列基础上，额外取 $\{\text{事件时间},\ \text{行为类型}\}$ 中存在的列。
- **重定位说明（纠偏）**：原图把 B 叫"交叉验证 / 因果验证"，那是**错的**——不同 cohort 人群本就不同，比留存率差异是选择性偏差，不是因果验证。本分支正确价值是**同期群质量时间趋势**：跨获客月看同偏移 $j$ 的留存 / ARPU 是在变好还是变差，对"投放质量是否提升"极有用。（**大白话**：这分支不是证明"因为啥所以留存变"，只是看"每个月拉来的人质量是不是在变好/变差"）
- **探测逻辑**：
  1. 对每个偏移 $j$（如 $j=1,3,6$），取所有纳入矩阵的 cohort $i$ 的 $Retention_{ij}$，连成随获客时间变化的时间序列（带 Wilson 95% CI 带）。
  2. 用**两比例 z 检验**比较相邻 cohort（cohort $i$ vs $i-1$）在同 $j$ 下的留存差异，显著则标 `*`：
     $$z = \frac{\hat{p}_1 - \hat{p}_2}{\sqrt{\hat{p}(1-\hat{p})(1/n_1 + 1/n_2)}},\quad \hat{p} = \frac{x_1+x_2}{n_1+n_2},\quad \alpha=0.05$$
  3. 若传入 `事件时间` / `行为类型`，可换"事件锚定 cohort"（以注册日 / 某行为日作锚点替代首购日），比较不同事件类型 cohort 的质量趋势。
- **输出数据**：各偏移 $j$ 的留存 / ARPU 质量趋势折线（含 CI 带与显著性 `*`）→ 暴露"投放质量是否在变好"盲区；明确注明为描述性趋势 + 统计检验，**不声称因果验证**。（**大白话**：画出"每个月质量走势线"，哪些月显著变好/变差打星号；但只说现象、不硬说因果）

### C 净毛利 / 净 GMV 净化（探测列：商品成本、退款金额、运费）· MD+2

> **大白话**：C＝前面算的"花了多少"是毛的，这里扣掉成本/退款/运费，看真正赚了多少。

- **取列与归月口径（后端写死普适默认，可配）**：
  - **运费归下单月**：运费是下单时确认的履约成本，随订单走，计入订单所属自然月（`SHIPPING_ATTR="order_month"`）。（**大白话**：运费是下单那一刻就定了的履约成本，跟订单走，算在下单那个月）
  - **退款归退款完成月**（不回朔原订单月）：财务上退款在"真退的那个月"才冲减收入；若回朔会扭曲原 cohort 历史数。无 `退款完成日期` 时 fallback 归订单月（`REFUND_ATTR="refund_month"`）。（**大白话**：退款可能买完很久才退，算在"真退那月"、不往回改首单月的数，否则历史被改坏）
  - 净口径：`净GMV(m) = Σ实付(m) − Σ退款(m)`；运费是否动取决于"订单实付金额"是否已含运费：含则不动，独立字段则通常计入成本而非收入（口径在文档标注）。
- **净毛利计算**（统一规则：**净毛利 = 订单实付金额 − 所取到的成本类列之和**，未取到项按 0；按实际传入列分三种情况）：
  - **三列全取**（商品成本、退款金额、运费 都传入）：
    $$NetMargin_o = \text{订单实付金额}_o - \text{商品成本}_o - \text{退款金额}_o(\text{归退款完成月}) - \text{运费}_o(\text{归下单月})$$
  - **只取一个**（仅其一传入）：只扣那一项，另两项按 0：
    $$NetMargin_o = \text{订单实付金额}_o - \text{商品成本}_o \qquad (\text{仅取到 商品成本})$$
    $$NetMargin_o = \text{订单实付金额}_o - \text{退款金额}_o \qquad (\text{仅取到 退款金额})$$
    $$NetMargin_o = \text{订单实付金额}_o - \text{运费}_o \qquad (\text{仅取到 运费})$$
  - **取两个**（任意两项传入）：扣对应两项，未取到项按 0，例（仅 商品成本 + 运费）：
    $$NetMargin_o = \text{订单实付金额}_o - \text{商品成本}_o - \text{运费}_o$$
- **聚合进 cohort**：用 $NetMargin_o$ 替换 2.3 的 $R_{ij} = \Sigma \text{订单实付金额}$，重算净毛利版格子 $R^{net}_{ij}$ 与 $ARPU^{net}_{ij} = R^{net}_{ij}/U_{ij}$，得到净毛利下三角矩阵。（**大白话**：把"花的钱"换成"净赚的钱"重算一遍那张三角表）
- **输出数据**：净毛利 cohort 矩阵 → 暴露"某 cohort 表面 ARPU 高但净毛利为负（亏本拉新）"盲区。

## 附录：可配常量表（后端写死默认 + 暴露覆盖）

> **大白话**：下面这些参数都能改，默认给的是最通用的电商口径（北京时间、满 6 个月才拿进来比、95% 置信等）。真有别的业务习惯，改默认值就行。

| 常量 | 默认值 | 含义 |
|---|---|---|
| `TZ` | `"Asia/Shanghai"`（即北京时间 UTC+8） | 所有"月"计算的时区基准 |
| `STATUS_WHITELIST` | `{已完成, 已支付}` | 订单状态白名单，其余（已取消/已退款/已关闭）剔除 |
| `FUTURE_TOLERANCE` | `1 day` | 订单时间超过 today 多少内算时钟漂移容差 |
| `FUTURE_SKIP_RATIO` | `0.05` | 未来时间行占比超此值则整体 `skipped` |
| `MIN_OBSERVATION_MONTHS` | `6` | 最小观察期：cohort 须成熟满 N 月才进基座矩阵 |
| `CONFIDENCE` | `0.95` | 置信区间与显著性检验水平（$\alpha=0.05$） |
| `REFUND_ATTR` | `"refund_month"` | 退款归月口径：退款完成月（无完成日 fallback 订单月） |
| `SHIPPING_ATTR` | `"order_month"` | 运费归月口径：随订单走，归下单月 |
