# CLV 客户生命周期价值模型 · 三段式算法拆解

> 核心作用：利用**历史客单价、购买频次、流失率**，估算单客在未来整个生命周期内能带来的**总营收**。
> 拆解逻辑（用户定的尺子）：第一段 硬性阻断层 HardBlock（把门）→ 第二段 基座计算层 Base（立核心，最优先）→ 第三段 进阶探测层 Advanced（从核心往深里挖）。
> 下游目的：本拆解即后端（Python / Pandas）代码规格——据此直接生成 `clv.py` 计算模块（`validate_input` + `compute_base` + `compute_advanced_a/b/c`）。

---

## 第一段：硬性阻断层（HardBlock）—— 输入数据校验

- **校验对象**：Pandas DataFrame 列名
- **必备列集**：$C_{core} = \{\text{用户ID},\ \text{订单时间},\ \text{订单实付金额},\ \text{订单ID}\}$
  - `用户ID`：分组主键（按用户聚合成一行）
  - `订单时间`：算购买频次的时间窗口、已存续期、最近购买间隔（推流失率）
  - `订单实付金额`：算历史总营收 $M$（客单价分子）
  - `订单ID`：算购买频次 $F$（去重订单笔数）
- **阻断**：若 $C_{core} \not\subset \text{原始列}$ → `return {"status":"skipped"}`（跳过非报错）
- **标注**：`MD 算法阻断`
- **取列**：仅做列名存在性校验，不取数；要求原始表含上述 4 列方可进入 Base。

> 白话：CLV 要算"每个人值多少钱"，底层就靠这 4 个原始列——谁买的（用户ID）、啥时候买（订单时间）、花多少（订单实付金额）、买了几单（订单ID）。缺一不可直接跳过，不报错。注意：**客单价、购买频次、流失率这仨不是原始列、不进白名单**，它们是 Base 内部从上面 4 列算出来的派生量（见第二段）。

## 第二段：基座计算层（Base Calculation）—— 模型最核心分析

**目标**：流水订单表（默认订单级，每笔订单一行）→ 每用户一行（客单价 / 年购买频次 / 群体流失率）→ 单客 **CLV**（未来全生命周期总营收，连续值）。这是 CLV 的灵魂，必须先立稳。

### 2.1 用户级指标聚合（User-level Aggregation）· MD 数学公式

- **取列**：从原始表取 $\{\text{用户ID},\ \text{订单时间},\ \text{订单ID},\ \text{订单实付金额}\}$ 四列；按 `用户ID` GroupBy，对每个用户算标量：
- ⚠️ **表粒度假设**：本模型默认输入为**订单级表**（每笔订单一行，`订单实付金额` 为订单级唯一值、`订单ID` 唯一）。若实际为明细级（同一订单拆多行），须先按 `订单ID` 去重 / 聚合金额（每订单取唯一 `订单实付金额`，或 sum 后按订单去重）再按用户汇总，否则 $M / M'$ 会重复累加失真。
$$M(u) = \sum \text{订单实付金额}_u$$
$$F(u) = \text{Nunique}(\text{订单ID}_u)$$
$$\text{first}(u) = \min(\text{订单时间}_u),\quad \text{last}(u) = \max(\text{订单时间}_u)$$
- **白话**：把每个用户的全部订单行压成一行——总花了多少 $M$、买了几单 $F$、首单和末单时间。
- **数据形状（Data Shape）**：用户级宽表 $[\text{用户ID},\ M,\ F,\ \text{first},\ \text{last}]$（每用户一行）。

### 2.2 客单价与年购买频次（AOV & Yearly Frequency）· MD 数学公式

- **取列**：取 2.1 输出 $[\text{用户ID},\ M,\ F,\ \text{first},\ \text{last}]$。
- **公式**：
$$\text{AOV}(u) = \frac{M(u)}{F(u)}$$
$$\text{tenure\_years}(u) = \max\!\left(1\ \text{天},\ \frac{T_{ref} - \text{first}(u)}{365}\right)$$
$$F_{yearly}(u) = \frac{F(u)}{\text{tenure\_years}(u)}$$
- **变量说明**：$T_{ref}$ = **数据快照基准日**，默认取数据中 $\max(\text{订单时间})$（全表最新一笔订单日），即这份数据集所代表的"当下"；**仅当数据是实时流（截至运行当日）时才取当前分析当日**。$\text{tenure\_years}$ 是"已存续年数"，下限夹 1 天避免除零；$\text{AOV}$ = 历史客单价，$F_{yearly}$ = 年购买频次。
- **白话**：客单价 = 总花销 ÷ 总单量；年购买频次 = 总单量 ÷ 活了多少年（比如活了 2 年买了 10 单 → 年均 5 单）。
- **数据形状**：宽表新增 $[\text{AOV},\ \text{tenure\_years},\ F_{yearly}]$。

### 2.3 群体流失率推导（Churn Rate，从原生列推，不进白名单）· MD 数学公式

- **取列**：取 2.1 输出 $[\text{用户ID},\ \text{last}]$ 与 $T_{ref}$。
- **公式**：
$$R(u) = T_{ref} - \text{last}(u) \quad\text{（最近购买间隔天数）}$$
$$\hat{c} = \frac{\bigl|\{u \mid R(u) > R_{churn}\}\bigr|}{N}$$
- **变量说明**：$R(u)$ 即映射词典"最近购买间隔天数"；$\hat{c}$ 为**截面群体流失占比**（已流失用户数 ÷ 总用户数），**本简化模型将其近似视为年化（每期）流失率**用于 2.4 的 $E[T]=1/\hat{c}$（几何分布期望寿命的近似前提）；更精确的分层 / 年化估计见进阶 C。$R_{churn}$ = 流失判定阈值，**可配常量，默认 180 天**（或取群体平均购买间隔 × 2，业务自定）。
- **白话**：用"多久没买了"判断一个人算不算流失——超过阈值（默认半年没买）就算流失。全公司流失人数占比，就是群体流失占比 $\hat{c}$；**2.4 把 $\hat{c}$ 近似当年化流失率**来估期望寿命，属简化假设（精确估计交给进阶 C）。**这一步不写死、不进白名单**：流失率是算出来的，不是数据里现成的。
- **数据形状**：输出标量 $\hat{c}$（全局）+ 每客 $R(u)$（宽表新增 $[R]$）。

### 2.4 单客 CLV 估算（核心输出）· MD 数学公式

- **取列**：取 $[\text{用户ID},\ \text{AOV},\ F_{yearly}]$ + 标量 $\hat{c}$。
- **公式**（统一口径，含可配折现率 $d$，默认 $0$ 即不折现）：
$$r = 1 - \hat{c} \quad\text{（年留存率）}$$
$$\text{CLV}(u) = \text{AOV}(u) \times F_{yearly}(u) \times \frac{r}{1 + d - r}$$
  - 直觉参考（几何分布期望寿命）：$E[T] = \frac{1}{\hat{c}}$（年），表示把截面流失占比 $\hat{c}$ 近似视为年化流失率时客户的期望剩余年数；⚠️ 此仅为直觉量，**CLV 实际以左侧折现闭合式为准**（当 $d=0$ 时 $\text{CLV}(u)=\text{AOV}(u)\times F_{yearly}(u)\times\frac{1-\hat{c}}{\hat{c}}$，与"年贡献 × $E[T]$"差 $(1-\hat{c})$ 因子，源于贡献从第 1 年才计入的级数边界，非错误）。
- **白话**：CLV = 每年贡献 × 折现留存因子。每年贡献 = 客单价 × 年购买频次。例：客单价 100、年买 5 次（年贡献 500）、流失率 20%（$r=0.8$）、折现率 $d=0$ → $\text{CLV} = 500 \times \frac{0.8}{0.2} = 2000$ 元。这就是"这个客户余生能给公司带来的总营收"估计值；调高 $d$ 即为未来营收折现（更保守）。
- **数据形状**：宽表新增 $[\text{CLV}]$（每用户一行连续值），可直接排序 / 分层。

**基座输出**：用户级宽表 $[\text{用户ID},\ M,\ F,\ \text{AOV},\ \text{tenure\_years},\ F_{yearly},\ R,\ \text{CLV}]$ + 群体流失率 $\hat{c}$。

### 2.5 基座可视化产出（计算层 → 决策层桥梁）

- **CLV 分布直方图**：数据来源 2.4 的 `CLV` 列。业务作用：看客户价值是否长尾（少数高 CLV 客户贡献大部分营收），定"头部客户"运营优先级。
- **CLV Top-N 排行榜**：数据来源 2.4 排序后取前 N。业务作用：直接拉出高价值客户清单做 1v1 维护 / VIP 服务。
- **CLV 分层条形图**（按分位切 高 / 中 / 低 价值）：数据来源 2.4 分位。业务作用：把连续 CLV 压成 3 档，对接运营资源分配（高价值重点维护、低价值控投入）。

## 第三段：进阶探测层（Advanced Probe）—— 从核心往深里挖

触发（入口契约）：每个分支**独立判断**——仅当自身**探测列**存在于输入、且其依赖的 Base 步已跑通时才调用对应 `compute_advanced_*`，多支可并存。各支探测列均为 Base 已用列的子集（或原生订单列），故入口判断 = 探测列存在性校验 + 依赖步成功校验（详见各支「入口 / 触发判断」）。基座不变，进阶只在其上叠加维度 / 换指标 / 换口径。

### A 渠道 / 类目细分 CLV（探测列：流量来源、商品类目）· MD+1

- **探测列**：$\{\text{流量来源},\ \text{商品类目}\}$ 中存在的列作为维度 $k$。
- **入口 / 触发判断**：A 站在 2.4 之上——对 2.4 产出的每客 `CLV` 按用户级维度归属 $k_u$ 取均值（口径见下方算法推导，统一方法②）。故依赖 **2.4 跑通**；**且**探测列 $\{\text{流量来源},\ \text{商品类目}\}$ 中**至少一个存在**才跑，逐列独立触发。代码入口：`compute_advanced_a(df, base_result)` 在 **2.4 返回运行成功后、且 `trigger = [c for c in ["流量来源","商品类目"] if c in df.columns]` 非空** 才调用。
- **算法推导变更**：**统一采用方法②（逐客均值）**——先为每用户确定其维度归属 $k_u$（维度列为用户级则直接使用；为订单级则用该用户消费金额占比最高的 $k$ 作为主归属），再对 2.4 算出的每客 `CLV` 按 $k_u$ 取均值：
$$\overline{\text{CLV}}(k) = \frac{1}{|\{u \mid k_u=k\}|}\sum_{u: k_u=k} \text{CLV}(u)$$
（不采用"按 $(\text{用户ID},\ 维度_k)$ 重算 $M/F$"的方法①：它会把多订单用户在订单级维度下切碎，与逐客 CLV 口径不一致。）
- **数学公式变更**：维度均值替代全局均值（每客 `CLV` 已含全局 $\hat{c}$，A 仅做按 $k_u$ 的均值聚合；若需维度级流失率分析，另行按维度算 $\hat{c}_k$，属扩展而非 A 默认动作）。
- **输出数据**：各渠道 / 类目平均 CLV 对比表 → 暴露"某渠道拉来的用户 CLV 偏低、质量差"盲区，指导投放预算倾斜。

### B 净 CLV 净化（探测列：商品成本、退款金额、运费）· MD+2

- **探测列**：$\{\text{商品成本},\ \text{退款金额},\ \text{运费}\}$ 中传入的列（统一规则：**净毛利 = 订单实付金额 − 所取到的成本类列之和**，未取到的项按 0）。
- **入口 / 触发判断**：B 改写净客单价——把 2.1 的 $M$ 换为净贡献 $M'$（→ 2.2 的 $\text{AOV}'$），再按 2.4 的 CLV 结构换分子重算 $\text{CLV}_{net}$（分母 $\hat{c}$、$F_{yearly}$ 复用 Base）。故依赖 **2.1 ∧ 2.2 ∧ 2.3 ∧ 2.4 全部跑通**（净 CLV 需 $M'/F/\hat{c}/F_{yearly}$ 四派生量俱在）；**且**探测列 $\{\text{商品成本},\ \text{退款金额},\ \text{运费}\}$ 中**至少一个存在**才跑，未取到的成本项按 0。代码入口：`compute_advanced_b(df, base_result)` 在 **四步全部返回运行成功后、且成本类列存在** 才调用。
- **算法推导变更**：改 2.2 的 $\text{AOV}$ 为净客单价，以 2.1 的 $M$ 改为净贡献 $M'$：
$$M'(u) = \sum\bigl(\text{订单实付金额} - \text{商品成本} - \text{退款金额} - \text{运费}\bigr)_u$$
$$\text{AOV}'(u) = \frac{M'(u)}{F(u)}$$
$$\text{CLV}_{net}(u) = \text{AOV}'(u) \times F_{yearly}(u) \times \frac{1-\hat{c}}{d + \hat{c}}$$
（与主公式统一口径：代入 $r=1-\hat{c}$ 得 $\frac{r}{1+d-r}=\frac{1-\hat{c}}{d+\hat{c}}$；$d$ 默认 $0$ 时 $=\text{AOV}'(u)\times F_{yearly}(u)\times\frac{1-\hat{c}}{\hat{c}}$。）
- **数学公式变更**：仅分子 $M \to M'$（分母 $\hat{c}$、$F_{yearly}$ 不变）。
- **输出数据**：净 CLV 宽表 → 暴露"高营收但净毛利为负、实则亏钱"的虚假高价值客户盲区（同 RFM 净毛利净化思路，但输出连续 CLV 值）。

### C 流失率精算（探测列：最后活跃时间、注册日期）· MD+1

- **探测列**：$\{\text{最后活跃时间},\ \text{注册日期}\}$ 中存在的列。
- **入口 / 触发判断**：C 改写 2.3 的 $R(u)$ 口径与 $\hat{c}$ 粒度（活跃口径或按客龄分层），再回代 2.4 重算 CLV。故依赖 **2.3 ∧ 2.4 跑通**；**且**探测列 $\{\text{最后活跃时间},\ \text{注册日期}\}$ 中**至少一个存在**才跑。代码入口：`compute_advanced_c(df, base_result)` 在 **2.3 ∧ 2.4 返回运行成功后、且探测列存在** 才调用。
- **算法推导变更**：改 2.3 的 $R(u)$ 口径与 $\hat{c}$ 粒度：
  - 用 `最后活跃时间` 替代 `订单时间` 的 $\text{last}$ 算 $R$（活跃信号比"末次下单"更灵敏，未下单但还在逛的客户不算流失）；
  - 或按 `注册日期` 分客龄层（新客 / 成长期 / 成熟期），分层算流失率 $\hat{c}_{age}$ 替代全局 $\hat{c}$，再回代 2.4。各客龄层 $a$ 的 $\hat{c}_{age}(a)$ 同 2.3 口径（该层内 $R(u)>R_{churn}$ 占比），仅分母限定为本层用户：
$$\hat{c}_{age}(a) = \frac{\bigl|\{u \in \text{层}a \mid R(u) > R_{churn}\}\bigr|}{N_a}$$
$$\text{CLV}(u) = \text{AOV}(u) \times F_{yearly}(u) \times \frac{1-\hat{c}_{age}(u)}{d + \hat{c}_{age}(u)}$$
（与主公式统一口径：用 $\hat{c}_{age}$ 替代全局 $\hat{c}$ 回代折现闭合式。）
- **数学公式变更**：$R$ 来源与 $\hat{c}$ 由"全局标量"变"按活跃口径 / 按客龄分层"。
- **输出数据**：分层流失率表 + 修正后 CLV → 暴露"不同客龄流失率差很大、全局流失率会高估老客价值"盲区。

### 进阶可视化产出（叠加在 Base 之上）

- **A 渠道 / 类目细分 → 分组条形图**：x = 渠道 / 类目，y = 平均 CLV。业务作用：对比各渠道用户价值，砍掉低 CLV 渠道。
- **B 净 CLV 净化 → 总 CLV vs 净 CLV 双轴图**：柱 = 总 CLV，线 = 净 CLV。业务作用：一眼看哪个客户"表面营收高、实际净亏"。
- **C 流失率精算 → 客龄 × 流失率折线 + 修正 CLV 对比**：业务作用：看清老客流失率其实远低于全局假设，修正后 CLV 更准。

## 与现有模块的衔接（不重复造轮子）

- **CLV 与 `USER_SEG` / `CHURN_SEG`（K-means 引擎）共享用户级聚合**：三者都要先算 $M/F/R$。CLV 是独立自包含模型（输出连续 CLV 值），不依赖 K-means；但 CLV 算出的 `CLV` 列可直接作为 `USER_SEG` 聚类特征或 `CHURN_SEG` 挽留优先级排序依据。
- **无降级兜底关系**：CLV 不像 RFM→USER_SEG 那样有降级链；CLV 自己 HardBlock 不齐就 `skipped`，不触发其他模块。
- **白名单铁律一致**：CLV 白名单只列原生列（`用户ID / 订单时间 / 订单实付金额 / 订单ID` + 进阶探测列），客单价 / 购买频次 / 流失率 等派生量一律不进白名单，由 Base 内部算出。

## 交叉校验结论

$C_{core}$（用户ID / 订单时间 / 订单实付金额 / 订单ID）与全部进阶探测列（流量来源 / 商品类目 / 商品成本 / 退款金额 / 运费 / 最后活跃时间 / 注册日期）均已存在于 `映射词典.md`，**无需扩充词典**。

> 注：映射词典中"总消费金额"含变体 `ltv` / `用户终身价值`——若上游直接传入该历史累计营收列，按白名单铁律它属派生量，**不进白名单**；CLV 一律从原生订单流水重算，不读取该列，保证口径统一。
