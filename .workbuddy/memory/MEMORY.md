# DataMind AI 项目 - 长期记忆

## 关键事实（影响所有简历/面试材料）
- **项目系用户用自然语言让 AI Agent 生成，用户未手写任何代码。** 因此简历必须诚实定位为「AI 辅助开发 / 用户主导设计与架构」，不可谎称「独立开发/自研」。
- 用户目标岗位：后端/平台开发实习生；简历中文一页；当前采用「诚实 AI 辅助 + 元技能信号」混合定位。
- 硬约束：**简历每条技术点用户必须能面试答辩**（讲清为什么这么设计）。做不到的需删或弱化。
- **开发工具 = CodeBuddy（AI 编程 Agent）。**
- **防遗忘/防改错的实际机制（可验证，已写进答辩文档）：**
  - `.codebuddy/rules.md`（162 行项目规则硬备份，Agent 每次必读）——"项目宪法"外置。
  - `.codebuddy/plans/`（含 B12/B13/B14 等 bug 修复计划）——改动归档。
  - Agent 根据用户修 bug 的固定打法（定位→根因→最小改动→验证→防回归）**自行总结出一个可复用的 skill `quality-assurance-sop`，已开源：github.com/linziquan/everything_skill（MIT）**；专治 Agent 的 rush/partial/false-completion，含五阶段工作流 + 置信度标签(✅/⚠️/🔍) + 根因两层 why + 用户验证清单。
- **RAG 问题双重答法**：产品侧没用 RAG（LLM 只收结构化已验证结论）；开发侧可答"用 rules.md+skill+plans 这种结构化外置记忆替代了 RAG，理解 RAG 原理，大代码库才上向量检索"。
