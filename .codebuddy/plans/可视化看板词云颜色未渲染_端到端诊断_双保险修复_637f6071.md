## 用户需求

仪表盘（DashboardPage）中的「可视化看板」（grid / medical 模板）里，词云图颜色没有渲染——词呈黑色或单色，而不是逐词多彩。

## 背景

此前在分析可视化（AnalysisPage）路径已修复过词云 color function（双签名兼容 + `EChartView.hydrateWordCloudColor` 水合），但看板场景仍报未渲染。看板词云图的 option 来自已保存分析包的 `pkg.charts` / `rendered_charts`，经过后端 `create_wordcloud` 生成（textStyle.color 为 function 源码字符串），前端 `EGridLayout` 与 `MedicalDashboard` 均把 `option` 传给 `EChartView`（含 hydrate）。

## 核心特征

- 静态排查显示：后端 `create_wordcloud` 已带正确的双签名 color function 字符串；`sanitize_json` 对字符串原样返回，不破坏；前端看板组件也走 `EChartView.hydrateWordCloudColor`。
- 隐患点：`hydrateWordCloudColor` 当前仅在 `textStyle.color` 是「以 function/(/=> 开头的 string」时才水合；若后端下发的 color 是**普通字符串 / 缺失 / 其它形式**，水合不会触发，`echarts-wordcloud` 会把无效颜色当默认黑色 → 黑色/单色。
- 用户实测失败，最可能原因：① 前后端服务未重启 / 浏览器缓存（上次修复未生效，最常见）；② 运行态特例导致看板词云 option 的 `textStyle.color` 实际非 function 字符串。

## 核心修复目标

1. 运行态诊断：确认看板链路实际下发的词云 option 的 `textStyle.color` 是否为合法 function 源码字符串。
2. 前端双保险：增强 `hydrateWordCloudColor`，当 color 缺失 / 非 function / 水合失败时，自动注入基于 `WORDCLOUD_PALETTE` 的兜底 color function（逐词取色），确保看板词云在任何情况下都渲染多彩，而非黑色/单色。
3. 若诊断发现后端下发异常，统一所有词云下发源复用 `create_wordcloud` 的 `color_func_js`。

## 技术栈

- 前端：React + TypeScript，图表渲染组件 `EChartView.tsx`（含 `echarts-wordcloud` 与 `hydrateWordCloudColor` 水合逻辑）
- 后端：Python，`src/echart_generator.py` 的 `create_wordcloud`（词云 option 生成，`textStyle.color` 为双签名 function 源码字符串），`backend/routers/dashboard.py` 的 `api_dashboard_echarts` / `_extract_chart_configs_from_packages`

## 实现方案

### 总体策略

分两阶段：**先运行态诊断确认根因，再实施前端双保险（与诊断结果无关、零风险必做），必要时补后端统一**。

### 关键技术决策

1. **诊断优先**：构造词云 AnalysisPackage → 经 session_manager 保存 → 走 `api_dashboard_echarts` 逻辑（`_extract_chart_configs_from_packages` + `create_echart` 回退）→ 打印返回的 wordcloud option 的 `series[0].textStyle.color` 实际字符串，确认是否以 `function` 开头。静态已确认链路正确，必须用运行态排除「服务未重启 / 缓存 / 运行态特例」。
2. **前端双保险（必做，零风险）**：增强 `hydrateWordCloudColor`——

- 若 `textStyle.color` 是合法 function 字符串：保持现有水合逻辑不变；
- 若水合抛错 / 是普通字符串（非 function）/ 缺失：一律注入基于 `WORDCLOUD_PALETTE` 的兜底 color function（按词 index/charCode 取色，兼容 echarts `function(params)` 调用），确保逐词多彩。
- 此改动不影响现有正常路径，仅为异常路径兜底，风险极低。

3. **后端统一（视诊断）**：若诊断显示看板词云 option 的 color 缺失 / 为普通字符串 / 被截断，则定位下发源（保存流程 `rendered_charts` 生成或某回退路径），统一所有 wordcloud 下发复用 `create_wordcloud.color_func_js`，消除「非 function 颜色」源头。

### 性能与可靠性

- `hydrateWordCloudColor` 仅在 wordcloud series 上执行，开销可忽略；兜底 color 函数为纯计算（charCode + 取模），无 I/O。
- 双保险不改变正常路径行为，向后兼容；不引入新依赖、不改色板 SSOT（`Palette.ts`/`ChartStyle.ts`）。

## 实现注意事项

- 仅改 `EChartView.tsx` 的 `hydrateWordCloudColor`（及新增内部 `makeFallbackColorFn`）；复用现有 `WORDCLOUD_PALETTE`（与后端 `BLUE_PALETTE` 点对点一致）。
- 后端若改，仅统一 wordcloud 下发的 color 来源，不触碰 `exportEChartsDashboard.ts`、BigScreen 美学、`GLMapView.tsx`、色板 SSOT、列选择（列选择修复已在上一轮完成）。
- 验证：诊断脚本断言 color 以 `function` 开头（预案 B 时）；前端 `npx tsc --noEmit` 零错误；最终提醒用户重启前后端 + 清浏览器缓存后复测。
