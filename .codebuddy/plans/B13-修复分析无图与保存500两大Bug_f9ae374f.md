## 用户问题

用户在执行数据洞察后，分析结果包（packages）中只有 KPI 卡片、表格和 insight 文本，**没有任何图表**。点击"保存到收藏"按钮报 **500 错误**。

## Bug1：图表缺失

- **现象**：前端 VisualizationRenderer 能正常渲染 ChartBlock（有 option 即渲染 ECharts），但后端返回的 `pkg.charts` 始终为空
- **三步断层**：

1. 模板创建了 `chart_data_list = [ChartData(...)]` 但 return 时 `charts=[]`（丢弃）
2. `analysis.py` 创建了 `_RENDERER = ChartRenderer()` 但从未调用
3. 路由直接 `dataclasses.asdict(result)` 返回，缺少渲染步骤

- 8 个模板全部受影响：6 个把 ChartData 错误塞进 charts 字段（类型不匹配），2 个直接留空

## Bug2：保存 500 错误

- **现象**：POST `/analysis/save` 返回 500
- **根因**：`session_manager.py:203` 用 `dict(dataclass_instance)` 做浅拷贝，嵌套的 KPIItem/TableData/ChartData 等 dataclass 保持为对象形式，FastAPI 序列化时无法处理

## 技术方案

### Bug1 修复架构：打通 ChartData → ChartRenderer → ChartItem 链路

设计意图（规划中的正确流程）：

```mermaid
flowchart LR
    A[模板 execute] -->|产出 chart_data_list| B[AnalysisPackage.chart_data]
    B --> C[路由 api_analysis_run]
    C -->|传入原始 df| D[ChartRenderer.render_all]
    D -->|填充| E[AnalysisPackage.charts]
    E --> F[sanitize_json 序列化]
    F --> G[前端 VisualizationRenderer]
```

当前断层：步骤 B 被跳过（模板丢弃 chart_data_list），步骤 D 从未执行。

**修复分三步：**

**第一步 — base.py 增加 chart_data 字段**
`AnalysisPackage` 新增 `chart_data: List[ChartData] = field(default_factory=list)`，作为模板与渲染器之间的数据桥梁。`charts` 字段保留（由渲染器在路由层填充）。

**第二步 — 8 个模板统一传递 chart_data**
每个模板将 `chart_data_list` 通过 `chart_data=` 传递到 AnalysisPackage。同时填充 `chart_data.data` 为实际的 DataFrame 记录（`to_dict('records')`），确保 ChartRenderer 能基于实际数据生成 ECharts option。

各模板数据填充策略：

| 模板 | 数据源形态 | 填充方式 |
| --- | --- | --- |
| growth_analysis | DataFrame(grouped) | `grouped.to_dict('records')` |
| ranking_analysis | Series(grouped) | `grouped.reset_index().to_dict('records')` |
| structure_analysis | Series(grouped) | `grouped.reset_index().to_dict('records')` |
| proportion_analysis | Series(grouped) | `grouped.reset_index().to_dict('records')` |
| concentration_analysis | Series(grouped) + cum_pct | 合并为 DataFrame 后 `to_dict('records')` |
| distribution_analysis | 原始列 series | `df[[metric]].to_dict('records')` |
| correlation_analysis | 原始列 df | `df[[dim, met]].dropna().to_dict('records')` |
| anomaly_analysis | 原始列 series | `df[[metric]].to_dict('records')` |


**第三步 — 路由层接入 ChartRenderer**
`analysis.py` 的 `api_analysis_run` 中，对每个 `result` 执行：

```python
result.charts = _RENDERER.render_all(result.chart_data)
```

`ChartRenderer.render_all()` 已实现，从 `chart_data.data` 构建 DataFrame 后调用 `create_chart()` 生成 ECharts option。无需修改 ChartRenderer。

### Bug2 修复：浅拷贝改为递归转换

`session_manager.py:203` 将 `dict(pkg)` 替换为 `dataclasses.asdict(pkg)`，递归展开所有嵌套 dataclass 为标准 Python 字典。同时添加 `import dataclasses`。

### 性能与可靠性

- `to_dict('records')` 在处理大数据时有一定开销，但对于分析结果包（通常几百行）影响可忽略
- `sanitize_json` 层（B12 已落地）会兜底处理所有 numpy/Python 特殊类型
- ChartRenderer.render() 已有 try/except 保护，单张图表渲染失败不会影响其他图表
- `dataclasses.asdict()` 是标准库方法，无额外依赖
