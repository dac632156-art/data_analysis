## 用户需求

部署上线的页面中,左侧导航侧边栏(Sidebar)最底部内容被遮挡(截图可见 `百炼新版需填:https://{空间ID}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` 与 `API Key` 文字片段),在 macOS 上表现为被 Dock 遮住、无法看到完整配置项。

## 产品概述

DataMind AI 数据分析工具的左侧固定侧边栏,包含 Logo、导航菜单、AI 模型/API 地址/API Key 配置区、数据信息区。

## 核心问题

侧边栏整体高度超过浏览器可视区域(或被 macOS Dock 常驻覆盖底部约 60–80px)时,最底部的「API Key 输入框」与「数据信息」被裁切在视口外/被 Dock 覆盖,且因容器未开启滚动,用户无法滚动到达这些内容。

## 核心修复目标

- 使侧边栏内容超高时可内部滚动,底部配置项始终可到达
- 配置项自然落位避开 Dock 覆盖区,不再被遮挡
- 不改变侧边栏宽度、层级、配色(银河紫体系)、视觉风格

## 技术栈

- 前端框架:React + TypeScript + Vite
- 样式:Tailwind CSS(原子类)
- 修改文件:`frontend/src/components/Layout/Sidebar.tsx`(唯一改动点)

## 实现方案

**方法**:通过修正 `aside` 的 flex 布局与溢出控制,让侧边栏在内容超高时内部滚动、并将配置区自然上移避开 Dock 覆盖区。

**根因**(已读 `Sidebar.tsx` 确认):

- L24 `<aside className="fixed left-0 top-0 h-screen w-64 z-20 flex flex-col">` 未设置 `overflow-y-auto`;
- L44 导航 `nav` 使用 `flex-1`,会把剩余空间全部吃掉,将 API Key 配置区与数据信息区顶到视口最底部(恰好落在 Dock 覆盖区);
- `h-screen` 固定全高 + 无滚动 → 底部内容被裁切且无滚动条可达。

**关键技术决策**:

1. `aside` 增加 `overflow-y-auto overflow-x-hidden`:内容超高时内部出现滚动条,底部配置项可滚动到达。
2. 导航 `nav` 由 `flex-1` 改为 `flex-shrink-0`(不再贪婪占满剩余空间):API Key 配置区自然落在导航下方的中下区域,避开 Dock 覆盖区;短屏时由 `aside` 的滚动兜底。
3. 给 `aside` 增加底部安全边距(`pb-16` 约 64px)与配置区 `flex-shrink-0`:确保滚动到底时最后一项与 Dock 间留有空隙,且不因 flex 收缩被压扁。

**性能与可靠性**:纯 CSS 布局修正,无 JS 逻辑改动、无重渲染开销;不改变既有 state/dispatch 链路,无回归风险。

## 实现注意

- 仅调整布局类,绝不改动 `z-20` 层级、宽度 `w-64`、背景/边框/辉光样式与银河紫配色,保持视觉一致。
- 为避免原生滚动条破坏暗色风格,可加 `scrollbar-width: thin` 的轻量内联样式(可选、非必须)。
- 修改后必须重新读取该文件确认类名已落地,并经前端构建/类型检查无报错。

## 架构设计

不涉及架构变更,仅修正单个组件布局。侧边栏仍由 `Layout` 在 `App` 中渲染,`DataContext` 的 state/dispatch 逻辑完全不变。
