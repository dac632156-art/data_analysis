## 问题概述

"分析可视化"页面中，用户跟 AI 对话后无法继续生成图表。具体表现为：

- **A) AI 对话回复后看不到分析计划列表**：后端 `/chat/analyze` 解析 intents 时缺少 `df` 参数，且 Agent 关键词白名单太窄，用户用自然语言提问时不会触发结构化 JSON 返回。
- **C) 聊天消息下方的「应用」按钮不生效**：`handleApplyInsights` 不接受参数导致传入的消息内容被丢弃，且函数内部有 `if (intents.length > 0) return` 短路逻辑阻止更新。

## 核心修复

1. 后端 `/chat/analyze` 解析 intents 时补传 `df` 参数，使 Step 3 规则兜底生效。
2. 扩展 Agent `analyze()` 的分析请求关键词白名单，覆盖更多自然语言变体。
3. 前端 `handleApplyInsights` 支持接收消息内容参数，点击「应用」时将该消息送回后端提取 intents 并更新列表。
4. 前端 `ChatResponse` 类型补上 `intents` 字段声明。

## 技术方案

### 修改文件清单

```
backend/routers/insights.py          # [MODIFY] Line 197: _parse_ai_result_to_intents(answer) → _parse_ai_result_to_intents(answer, df)
src/ai_agent/agent.py                # [MODIFY] Lines 103-105: 关键词白名单从 16 词扩展到 32 词
frontend/src/types/api.ts            # [MODIFY] ChatResponse 增加 intents 可选字段
frontend/src/pages/AnalysisPage.tsx  # [MODIFY] handleApplyInsights 签名改为 async (content?: string) =>，增加内容提取分支
```

### 实现方案

#### 1. 后端：补传 df 参数（insights.py）

- 第 197 行 `_parse_ai_result_to_intents(answer)` 改为 `_parse_ai_result_to_intents(answer, df)`
- 影响：当 AI 返回非 JSON 文本时，Step 3 规则兜底（Planner.generate_default_intents）能正常生成默认 intents，不再返回空列表
- `/insights/generate` 路线已正确传参，本次对齐

#### 2. 后端：扩展关键词白名单（agent.py）

- 新增自然语言关键词：`'规律', '特点', '特征', '关系', '变化', '增长', '下降', '排名', '占比', '构成', '分类', '分组', '比较', '看看', '查看', '展示', '画图', '作图', '怎么样', '如何', '哪个', '哪些'`
- 用户说"帮我看看数据有什么规律""哪些产品卖得好"等自然表述将触发结构化 JSON 返回路径
- 不影响原有关键词匹配逻辑，纯扩展

#### 3. 前端：修复 handleApplyInsights（AnalysisPage.tsx）

- 签名改为 `const handleApplyInsights = async (content?: string) =>`
- 新增 `content` 参数分支：调用 `api.chatAnalyze()` 将消息内容作为上下文送回后端提取 intents，提取成功后 `setIntents` 更新列表
- 无参数调用（第 716、869 行的一键生成按钮）保持原有行为不变
- 后向兼容：3 处调用点全部兼容

#### 4. 前端：ChatResponse 类型补全（api.ts）

- `ChatResponse` 增加 `intents?: Array<Record<string, string>>` 字段
- 运行时已存在该字段，纯类型修复

### 边界与约束

- 不新增后端路由，复用既有 `/chat/analyze`
- 不改变 `/insights/generate` 行为
- 「应用」按钮提取 intents 后仅更新列表，不自动执行分析（用户仍需勾选后点「执行分析」）
- 后端关键词扩展仅影响 `analyze()` 方法的分支判断，不改变 LLM prompt 内容
