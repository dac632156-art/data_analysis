## 用户需求

执行后端「层级 B」清理：彻底移除前端从未直接调用的 `/api/chat` 兼容别名端点。

- 删除 `backend/routers/chat.py`（纯转发别名文件，仅被 main.py 引用）
- 去掉 `backend/routers/insights.py:171` 的 `@router.post("/chat")` 装饰器，仅保留 `:170` 的 `/api/chat/analyze` 端点
- 同步清理 `backend/main.py` 中对 chat 路由的 import 与注册，避免后端启动 ImportError

## 核心特性

- 仅移除确无内部引用的冗余端点，前端 AI 对话（依赖 `/api/chat/analyze`）不受影响
- 全仓搜索 `/api/chat` 裸端点引用应在删除后彻底消失
- 改动仅限后端 3 个文件，无前端/配置/架构变更
- 改动留本地，不主动 commit/push

## Tech Stack

- 后端：Python + FastAPI（仅删文件、去装饰器、清理 import，无逻辑改动）
- 验证：grep 残留引用 + Python import 启动校验

## Implementation Approach

采用「最小爆破半径」清理：先改 insights.py 去掉裸端点装饰器，再删 chat.py 并同步清 main.py 两处引用，最后做全仓残留校验。

- **insights.py**：`api_chat_analyze` 函数本体、逻辑、错误处理全部保留，仅移除 `:171` 的 `@router.post("/chat")` 装饰器，使该视图函数只绑定 `/chat/analyze` 一个 URL。前端 `AnalysisPage.tsx` 调用的 `api.post('/chat/analyze')` 不受影响。
- **chat.py**：纯转发别名（`chat_analyze` → `await api_chat_analyze(req)`），全仓除 main.py 外 0 引用，直接删除文件。
- **main.py**：删除 `:23` import 行的 `chat,` 与 `:58` 的 `app.include_router(chat.router, ...)`，否则后端启动时 `ModuleNotFoundError/ImportError` 导致整个应用无法启动（这是必做清理，非风险）。

## Implementation Notes

- 删除后必须用 grep 全仓 `/api/chat`（裸，不含 `/analyze`）确认命中为 0；`/api/chat/analyze` 应仍存在（insights.py:170）。
- 后端启动校验：用 `python -c "from backend.main import app"` 或 `uvicorn backend.main:app` 启动观察无 ImportError；重点确认 `insights.py` 的 `api_chat_analyze` 仍可正常注册。
- 严禁触碰 `insights.py` 中 `api_chat_analyze` 函数体、前端 `client.ts:430` 的 `/chat/analyze` 调用，及 `data.py/dashboard.py/clean.py/agent.py` 里的 OpenAI SDK `client.chat.completions.create`（与 `/api/chat` HTTP 路由无关）。
- 不动现有前端死代码清理 plan（DashboardV2Page/.bak/CardGrid/helpers），本任务独立。

本次为纯删除型清理，不改变任何架构、调用链与数据流。后端路由注册由 11 个减为 10 个（移除 chat），前端路由与所有页面组件不变。
