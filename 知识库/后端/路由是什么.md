# 路由是什么

> 结合 [[FastAPI详解|DataMind AI 后端]] 实际代码讲解。建议先读 [[API的构成与种类]]。

## 一句话定义

**路由（Route）= 一张"请求地址 + 请求方式 → 处理函数"的映射表。**

它就像后端的**电话总机 / 前台接待**：看到来访者报的"门牌号（URL 路径）"和"来意（HTTP 方法）"，就知道该把请求转给哪个"坐席（函数）"处理。

```python
@router.post("/data/preview")          # ← 路由：门牌号 + 来意
async def data_preview(req: PreviewRequest):  # ← 坐席：处理函数
    """获取数据预览"""
```

三者缺一就不是一条完整路由：

| 组成 | 比喻 | 项目例子 |
|---|---|---|
| **URL 路径** | 门牌号 | `/data/preview` |
| **HTTP 方法** | 来意（GET=查 / POST=提交） | `POST` |
| **处理函数** | 坐席（真正干活的代码） | `data_preview` |

> 注意：路由是 [[API的构成与种类]] 里"Web API 三件套"中的"路径 + 方法"两件套；第三件套"处理函数"就挂在路由后面。所以**路由决定了"请求打到哪"，函数决定了"打到之后干什么"**。

## 本项目里路由的两种写法

后端有 10 个业务模块，分两类注册方式：

### 写法 A：直接挂在 `app` 上（主应用级路由）

用于全局、基础设施类接口，写在 `backend/main.py`：

```python
# backend/main.py
@app.get("/api/health")
async def health_check():
    """健康检查接口"""

@app.get("/api/session/new")
async def new_session():
    """创建新会话"""
```

还有一条**兜底路由**（SPA fallback），用 `{full_path:path}` 通配符接住所有非 `/api` 的 GET，回退到前端页面：

```python
@app.get("/{full_path:path}")
async def serve_spa(full_path: str):
    ...
```

### 写法 B：用 `APIRouter` 分组（模块化路由）

10 个业务模块各自是一个 `router` 文件，写在 `backend/routers/` 下：

```python
# backend/routers/data.py
router = APIRouter()

@router.post("/data/preview")
async def data_preview(req: PreviewRequest):
    ...

# backend/routers/clean.py
router = APIRouter()

@router.post("/clean/missing-report")
async def api_missing_report(req: SessionRequest):
    ...
```

最后由 `main.py` 统一"挂载"到主应用，并统一加 `/api` 前缀：

```python
# backend/main.py  L50-60
app.include_router(upload.router,    prefix="/api", tags=["数据上传"])
app.include_router(data.router,      prefix="/api", tags=["数据操作"])
app.include_router(clean.router,     prefix="/api", tags=["数据清洗"])
app.include_router(stats.router,     prefix="/api", tags=["统计分析"])
app.include_router(chart.router,     prefix="/api", tags=["图表生成"])
app.include_router(dashboard.router, prefix="/api", tags=["仪表盘"])
app.include_router(insights.router,  prefix="/api", tags=["AI 洞察"])
app.include_router(report.router,    prefix="/api", tags=["报告生成"])
app.include_router(analysis.router,  prefix="/api", tags=["分析执行"])
app.include_router(reasoning.router, prefix="/api", tags=["业务推理"])
```

**两种写法本质一样**，只是 B 把路由"先分文件夹、再统一接线"。为什么分？因为 50+ 条路由放一个文件会爆炸，按业务拆开更好维护。

## 路径是怎么拼出来的：prefix + 文件内路径

最终对外暴露的完整 URL = `prefix` + 文件内写的路径：

```
prefix="/api"  +  "/clean/missing-report"  =  POST /api/clean/missing-report
```

所以前端在 `client.ts` 里调接口时，URL **必须带 `/api` 前缀且方法一致**才能对上——这正是 [[API调用是什么]] 里"前端调后端"那一层要精确匹配的地方。

## 路径里的"变量"：路径参数

路径里用 `{名字}` 可以接收动态参数。比如查某个上传排队任务的状态：

```python
# backend/routers/upload.py
@router.get("/upload/queue/{ticket_id}")
async def queue_status(ticket_id: str):
    """ticket_id 会从 URL 里自动提取，例如 /upload/queue/abc123 → ticket_id='abc123'"""
```

对比：查询参数（`?a=1&b=2`）走 `?`，路径参数走 URL 路径本身，语义上"这个 id 是资源的一部分"。

## 一个完整路由处理函数长什么样

以 `data_preview` 为例，一条路由从"接到请求"到"返回"的全过程：

```python
@router.post("/data/preview")
async def data_preview(req: PreviewRequest):
    # ① req 已被 Pydantic 自动解析校验（见 [[FastAPI详解]] ④⑤）
    df = manager.get_dataframe(req.session_id)   # ② 取会话数据
    if df is None:
        raise HTTPException(status_code=404, detail="数据未找到")  # ③ 边界处理
    preview = df.head(req.rows).to_dict("records")
    return sanitize_json({                       # ④ 返回 dict，FastAPI 自动转 JSON
        "columns": list(df.columns),
        "rows": preview,
    })
```

链路对应 [[FastAPI详解]] 末尾的"请求全链路"：路由匹配 → 函数执行 → `return dict` 自动 JSON 序列化。

## 本项目路由全景表（按模块）

| 模块文件 | 前缀 | 代表路由 | 作用 |
|---|---|---|---|
| `main.py` | — | `GET /api/health` | 健康检查 |
| `main.py` | — | `GET /api/session/new` | 创建会话 |
| `upload.py` | `/api` | `POST /api/upload` | 上传文件 |
| `upload.py` | `/api` | `POST /api/upload/gate` | 上传闸门/排队 |
| `data.py` | `/api` | `POST /api/data/preview` | 数据预览 |
| `clean.py` | `/api` | `POST /api/clean/missing-report` | 缺失值报告 |
| `clean.py` | `/api` | `POST /api/clean/detect-outliers` | 异常值检测 |
| `stats.py` | `/api` | `POST /api/stats/descriptive` | 描述性统计 |
| `stats.py` | `/api` | `POST /api/stats/correlation` | 相关性矩阵 |
| `chart.py` | `/api` | `POST /api/chart/echart-create` | 生成 ECharts |
| `dashboard.py` | `/api` | `POST /api/dashboard/cards` | 卡片生成 |
| `dashboard.py` | `/api` | `POST /api/dashboard/kpis` | KPI 指标 |
| `insights.py` | `/api` | `POST /api/insights/generate` | AI 洞察 |
| `insights.py` | `/api` | `POST /api/chat/analyze` | 对话分析 |
| `report.py` | `/api` | `POST /api/report/ai-analyze` | AI 报告 |
| `analysis.py` | `/api` | `POST /api/analysis/...` | 分析执行 |
| `reasoning.py` | `/api` | `POST /api/reasoning/run` | 业务推理 |

> 命名规律：路径第一段 = 业务域（`upload`/`data`/`clean`/`stats`/`chart`/`dashboard`/`insights`/`report`/`analysis`/`reasoning`），和 `routers/` 文件名一一对应。这就是 [[RESTful API是什么]] 里"用 URL 定位资源"的落地。

## 路由与 HTTP 方法怎么选

| 方法 | 语义 | 项目例子 |
|---|---|---|
| `GET` | 查/读，幂等，参数走 URL | `/api/health`、`/upload/queue/{id}` |
| `POST` | 提交/计算，带请求体 | `/api/data/preview`、`/api/chart/echart-create` |
| `PUT` | 整体更新（本项目少用） | — |
| `DELETE` | 删除（本项目少用） | `/api/dashboard/delete-saved-chart` |

> 为什么本项目绝大多数用 `POST`？因为分析/统计的请求体是复杂 JSON（带 `session_id`、列名、参数），放 URL 里既不安全也不便；`GET` 只留给无请求体、可缓存的简单查询。
