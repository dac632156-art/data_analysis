# 同步与异步是什么（及区别）

> 结合 [[后端技术栈|DataMind AI 后端]] 实际代码讲解。这是理解 [[ASGI是什么]]、[[FastAPI详解]] 里 `async/await` 的前提。

## 一句话定义

- **同步（Synchronous）**：做事「一件接一件」，前一件没干完，后一件就不能开始；发起调用后**一直等到结果返回**才继续。本质是**阻塞**。
- **异步（Asynchronous）**：发起调用后**不干等**，先去处理别的事，等任务完成（或「叫号」）再回来取结果。本质是**非阻塞**。

## 核心区别对比

| 维度 | 同步 | 异步 |
|---|---|---|
| 执行方式 | 顺序、阻塞，A 没完 B 不能开始 | 发起后不等待，先去做别的 |
| 调用方状态 | 卡在调用处，线程被占用 | 立即腾出线程去处理其他任务 |
| I/O 等待（如查库、调 LLM） | 线程干等，资源浪费 | 把控制权交还，线程服务下一个请求 |
| 并发能力 | 靠「开更多线程」堆（成本高） | 单线程靠事件循环调度大量任务（高并发） |
| 编程模型 | 直来直去，好懂 | 早期回调地狱，现在 `async/await` 接近同步写法 |
| 本项目对应 | 旧 WSGI（Flask 时代） | **FastAPI + uvicorn（ASGI）** |

## 项目中的真实体现

**同步（阻塞）的样子**：一个请求进来，处理函数里要调 LLM。同步模式下，这个线程就在 `requests.post(llm)` 这里**干等**几秒，期间什么也干不了，后面排队的请求只能傻等或等新开线程。

**异步（非阻塞）的样子**（`backend/` 里 FastAPI 的写法）：

```python
@app.post("/api/insights/generate")
async def api_generate_insights(req: SessionRequest):
    # async def + await：调 LLM 时把线程"交还"事件循环
    result = await agent.generate_insights(df)   # 等待期间，uvicorn 去接别的请求
    return result
```

`await` 的关键作用：执行到这一行，**当前请求暂停、线程让出**，uvicorn 的事件循环转去处理其他请求；等 LLM 返回，再回来接着跑。于是**一个线程也能同时"服务"很多正在等 I/O 的请求**——这就是 FastAPI 高并发调 LLM 的底层原因。详见 [[ASGI是什么]]、[[uvicorn是什么]]。

## 类比

**同步 = 柜台点餐排队**：你站在窗口前，等厨师把你的饭做好递给你才离开，后面的人只能干等你。

**异步 = 取号点餐**：你取号后去旁边坐着（不占窗口），窗口一直能接下一位；饭好了「叫号」，你再回来取。窗口（线程）始终在高效运转。

> 更精确的对应：同步 ≈ **阻塞 I/O**；异步 ≈ **非阻塞 I/O + 事件循环**。

## 常见误解

| 误解 | 正解 |
|---|---|
| 异步 = 多线程 | ❌ 异步常是**单线程**靠事件循环切换；多线程是另一种并发手段，二者可叠加但不是一回事 |
| 用了 FastAPI 就自动异步 | ⚠️ 必须写 `async def` + `await`，且配 ASGI 服务器（uvicorn）才真正异步；写成普通 `def` 仍按线程池跑 |
| 异步一定比同步快 | ❌ CPU 密集任务（纯计算）用异步反而因调度开销更慢；异步优势在 **I/O 等待多** 的场景（本项目调 LLM、查库正是这类） |
