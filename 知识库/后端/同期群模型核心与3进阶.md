# 同期群模型核心与3进阶

同期群与用户状态跃迁模型（`src/analysis_engine/models/cohort.py`）是分析引擎的一个确定性模型，三段式：`HardBlock(validate_input)` → `Base(compute_base)` → `Advanced(a/b/c)`。产出图表数量随数据列而变，**最多 7 张**。

## 分层与 slot 前缀

每个图在 `compute()` 里通过 `ChartData(slot=...)` 生成，**slot 前缀即层级标识**，是判断"哪些被用到"的唯一可靠依据：

| 层级 | 触发条件（数据依赖） | slot 前缀 | 产出图（title / chart_type） |
|------|------|------|------|
| **核心 Base** | 满足 3 必填列（用户ID / 订单时间 / 订单实付金额）就出 | `cohort_retention`<br>`cohort_arpu` | 各同期群留存率（下三角）/ `cohort_heatmap`<br>各同期群客单价 ARPU（下三角）/ `cohort_heatmap` |
| **进阶 A** 渠道/类目升维 | 有「流量来源」列 → 1 张；有「商品类目」列 → 1 张；都没有 → 0 张（不报错） | `cohort_a_流量来源`<br>`cohort_a_商品类目` | *各渠道 M1 留存用户数（堆叠）* / `cohort_stacked` |
| **进阶 B** 质量趋势 | 有 ≥2 个成熟同期群（首单月距今满 6 个月观察期）就出 | `cohort_b_trend` | 同期群质量趋势（偏移 j 留存率）/ `cohort_trend` |
| **进阶 C** 净毛利净化 | 只要有成熟同期群就出（代码按 0 兜底成本，纯订单表也出） | `cohort_c_netmargin_heat`<br>`cohort_c_dual` | 各同期群净毛利 ARPU（下三角）/ `cohort_heatmap`<br>净GMV vs 净毛利（按同期群）/ `dual_axis` |

> 成熟同期群 = 首单月距今 ≥ 6 个月（`CohortConfig.MIN_OBSERVATION_MONTHS=6`）。

## 怎么确认"都用到"了

1. **看屏幕**：分析页 / 看板渲染的图表标题，对照上表数一数。
2. **看接口返回**：`AnalysisPackage.chart_data` 数组，每个元素带 `slot` + `title`，前缀即层级。
3. **眼见为实**：任意真实 CSV 丢进 `run_analysis(df, [])`，按 slot 前缀打印层级 + 标题。

```python
from src.analysis_engine.engine import run_analysis
packages = run_analysis(df, [])
for p in packages:
    for c in p.chart_data:
        slot = c.slot
        if slot.startswith("cohort_a_"):
            lvl = "进阶A"
        elif slot == "cohort_b_trend":
            lvl = "进阶B"
        elif slot.startswith("cohort_c_"):
            lvl = "进阶C"
        else:
            lvl = "核心"
        print(f"[{lvl}] {slot}  {c.title}")
```

## 关键提醒

**不是永远 7 图。** 满配 7 图 = 数据同时具备「流量来源」+「商品类目」两列、且 ≥2 个成熟同期群。缺这两列时进阶 A 可能 1 张甚至 0 张——正常，非 bug。进阶 B / C 几乎必然出（只要数据够老）。

## 与列名映射的关系

核心与进阶能否触发，前提是模型能识别数据列 → 依赖 `COLUMN_ALIASES`（`cohort.py`）与全局映射词典（`column_mapping_dict.yaml`）。例如「订单金额」必须作为「订单实付金额」别名，模型才认得；「退款状态」须作为「退款完成日期」别名，进阶 C 才能做退款月归因。详见 [[列名映射子系统]]。
