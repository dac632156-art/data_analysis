# 板块分层纪律

> 永久架构约束：三大功能板块各司其职，互不越界。任何改动都不得把「分析 / 处理 / 生图」能力塞进数据上传页或数据清洗页。

## 三板块职责边界

| 板块 | 只能做什么 | 绝对不能做 |
|---|---|---|
| 数据上传 | 拖文件上传、已上传列表展示、单表删除、一键删除全部、释放插槽 | 触发任何分析 / 处理 / 生图 |
| 数据清洗 | 缺失值 / 异常值 / 重复值 / 数据类型转换的 AI 方案 + 后端确定性执行，带快照回撤 | 做分析、生图 |
| 分析可视化 | 让 LLM 做分析决策 + 后端计算生图，呈现图表 | 不该出现在上传 / 清洗页 |

## 佐证（权威来源）

- `项目总结！！！.md` 第 1–3 点：数据上传 → 数据清洗 → 数据洞察（点击分析时后端先对清洗好的数据做列名映射 + 多表外键合并）→ 仪表盘，四步顺序。
- `backend/routers/analysis.py` L126-127 契约注释：「进入本函数时数据集已是清洗后状态（清洗由用户在按开始分析前用 `/clean/*` 交互完成），不再触发清洗。」
- 导航栏（各 `.yaml` 截图）即 4 个独立步骤页：数据上传 / 数据清洗 / 分析可视化 / 仪表盘。

## 反例（本次违规与整改）

- **违规**：数据上传页曾存在「一键处理全部报表」+ 每张表的「处理此表」按钮，点击直接 `processDatasets → 分析引擎跑图`，**绕过了独立的「数据清洗」步骤**，违反分层纪律。
- **整改（2026-07-25）**：上传页移除全部分析入口；「一键处理全部报表」改为「一键删除全部报表」（复用 `releaseUploadSlot` 清空数据）；「处理此表」按钮及其牵连的 `startProcess` / `pollStatus` / `processStatus` / `badge` 逻辑整块删除（经 search 确认仅 `UploadPage.tsx` 内部使用，分析可视化页不依赖）。
