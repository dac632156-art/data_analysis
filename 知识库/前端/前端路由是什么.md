# 前端路由是什么

> 一句话：**前端路由是在「不刷新整个页面」的前提下，根据 URL 切换显示哪块界面的机制**。它是单页应用（SPA）能「看起来像多个页面、实际只有一个 HTML 文件」的关键。

## 一、没有路由会怎样

传统网站：点一个链接 → 浏览器向服务器请求一个新 `.html` → 整页刷新。

单页应用（SPA，本项目就是）：**整个应用只加载一次 HTML**，之后所有「跳转」都不找服务器要新页面，而是**前端自己换掉屏幕上的内容**。

> 类比：传统网站像「每去一个房间就重建整栋楼」；SPA + 前端路由像「楼只建一次，你只是走到不同的房间，门牌（URL）变了，看到的家具（界面）不同」。

## 二、路由解决的核心问题

| 问题 | 没有路由 | 有路由 |
|---|---|---|
| 切换界面 | 整页刷新、慢、丢状态 | 局部替换、快、状态保留 |
| URL 与界面 | 不对应，刷新就回首页 | URL ↔ 界面一一对应，可收藏/分享 |
| 前进/后退 | 浏览器历史是整页 | 历史是「视图」，后退正常 |
| 直达某页 | 不行 | 直接输入 URL 就能进对应界面 |

## 三、它是怎么工作的（原理）

路由库（本项目用 **react-router-dom 6**）做的事：

1. **拦截**浏览器的地址变化（点链接、输 URL、按后退）—— 阻止整页刷新。
2. **匹配**当前 URL 到一个「规则表」（哪个路径对应哪个组件）。
3. **渲染**匹配到的组件，替换页面上的一块区域。

代码形态（v6 写法）：

```tsx
// App.tsx 里定义「URL → 页面组件」的映射
<Routes>
  <Route path="/"        element={<DashboardPage />} />   {/* 根路径 → 看板页 */}
  <Route path="/upload"  element={<UploadPage />} />     {/* /upload → 上传页 */}
  <Route path="/analyze" element={<AnalyzePage />} />    {/* /analyze → 分析页 */}
</Routes>
```

- 用户访问 `/upload` → 屏幕显示 `<UploadPage/>`，URL 栏也显示 `/upload`，但**页面没重新加载**。
- 点别的链接 → 只换中间那块，顶部/侧边导航（如果抽成公共布局）保持不变。

## 四、本项目怎么用（结合真实代码）

- **路由库**：`react-router-dom` 6（在前端技术栈表里已登记）。
- **路由表位置**：顶层 `App.tsx`，用 `<Routes>/<Route>` 把路径映射到 `pages/` 下的各个页面组件（上传、分析、看板、报告等）。
- **切换方式**：页面内的导航（侧边栏/顶部菜单）用 `<Link to="/analyze">` 或 `useNavigate()` 跳转，而不是 `<a href>`（后者会整页刷新，破坏 SPA）。
- **开发代理**：本地开发时，URL 里以 `/api` 开头的请求**不走前端路由**，而是被 Vite 代理转发到后端 `localhost:8001`（见 [[Vite是什么]]）；只有非 `/api` 的 URL 才归路由管。

## 五、和「后端路由」的区别（易混）

| | 前端路由 | 后端路由（如 FastAPI） |
|---|---|---|
| 发生在 | 浏览器里 | 服务器上 |
| 切换的是 | 屏幕上显示的 React 组件 | 返回哪段数据/HTML |
| 是否整页刷新 | 否（SPA 核心） | 每次请求都是新响应 |
| 本项目对应 | `App.tsx` 的 `<Routes>` | `backend/` 里 11 个 API 路由 |

> 两者都叫「路由」，但前端路由管「显示什么界面」，后端路由管「数据怎么取」。一次完整交互里它们配合：前端路由决定进哪个页面 → 该页面用 [[前端怎么调后端API]] 去调后端路由拿数据。
