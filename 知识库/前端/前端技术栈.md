## 三、前端目录结构（来自真实 `frontend/src/`）

| 目录 / 文件 | 职责 |
|---|---|
| `main.tsx` | 入口：把 `<App/>` 挂到 `index.html` 的 `#root` |
| `App.tsx` | 顶层组件 + 路由表（哪个 URL 显示哪个页面） |
| `pages/` | 各页面（上传、分析、看板、报告等） |
| `components/` | 可复用 UI 组件（34 个文件） |
| `api/` | 后端接口封装（统一走 axios + `/api` 前缀） |
| `contexts/` | React Context，跨组件共享状态 |
| `theme/` | 设计系统（VDS）：调色板、主题变量、图表样式（10 个 ts） |
| `types/` | TypeScript 类型定义 |
| `utils/` | 工具函数（导出 HTML、颜色、格式化等） |
| `assets/` | 静态资源（图片、svg） |
| `index.css` / `App.css` | 全局与组件样式（含 Tailwind 指令） |

## 四、一次「前端 → 后端」的交互链路（谁接谁）

```
浏览器（用户点击）
  → React 组件（页面/按钮）                    ← [[React是什么]]
  → api/ 封装（axios 发请求，URL 以 /api 开头）  ← [[前端怎么调后端API]]
  → Vite dev server 的 /api 代理               ← [[Vite是什么]]
       （开发时把 /api/* 转发到 http://localhost:8001）
  → 后端 uvicorn + FastAPI（真正的业务逻辑）     ← [[uvicorn是什么]] / [[FastAPI详解]]
  → 返回 JSON → axios 拿到 → React 用 state 更新界面
```

> 生产环境没有 Vite 代理：前端打包成静态文件，由后端（或 Vercel/Render）直接托管，`/api` 请求走真实域名。
